# 0006 · Part 2 of the agent Series: "The roadmap"

Status: planned

Product spec only. The Post will be `src/content/posts/2026-11-04-the-roadmap.mdx` (renamed to the real date when published) in the Series `src/content/series/building-an-agent-from-scratch.md`; see [GLOSSARY.md](../GLOSSARY.md) for Post, Draft, Series, Part, Planned Part, Companion repo and Snapshot, and [spec 0003](0003-agent-loop-post.md) for how Part 1 was ported.

## Problem statement

Part 1 ends with an agent that works and breaks in five ways: few tools and a crash when one throws, no way to test it without a live model, no memory across runs, no guardrails, and one near-copy of the loop per protocol. The next Parts each fix one of these, but a reader of the Series cannot see why they come in this order. The roadmap already exists as a lesson written in Vlad's OpenCode fork (`lessons/0002-the-roadmap.html`, generated by another Claude session). It needs to become Part 2, reading and looking like Part 1.

## Solution

A faithful port of the lesson as one Post, lightly edited for the blog. It stays a Draft until Vlad has read it.

- **Front matter**: category Agentic AI, tags `agents`, `architecture`, `opencode`, Series _Building an agent from scratch_, Part 2. No Snapshot, because this Part has no code of its own, so its footer links to the Companion repo root.
- **Content**: the five failures of the Part 1 agent; the Harness / Session / Sandbox framing from Anthropic's Managed Agents post; the vocabulary the map uses; the map in three stages (Harness, Session, Sandbox), each saying which failures it fixes; the safety note about adding a `bash` tool early; the Effect v4 note; the closing "defend your design" capstone.
- **Parts, not modules**: the lesson's "module" is "Part" throughout. Stage A items are referred to by Part number and Planned Part title in italics, unlinked (readers cannot open them yet), exactly matching the Series' Planned Parts: Part 3 _Tools as data_, Part 4 _Providers behind one interface_, Part 5 _Why Effect: errors as values_, Part 6 _Services and layers_, Part 7 _Streaming_. The lesson's `done` / `next` badges are dropped, since they would go stale as soon as the next Part ships.
- **Stages B and C** are described by intent but get no Part numbers and are not added to the Series' Planned Parts; per spec 0003 they join the Series only when Stage A is nearly done.
- **Vocabulary**: Part 1 already defines provider, protocol and model, so this Part only recalls them in one line and defines the three it adds: route, step, turn. It says once that "Session" here is agent vocabulary, unrelated to a blog Series.
- **Exercises**: all nine of the lesson's "Check yourself" questions (two recall questions from Part 1, four sort-into-Harness/Session/Sandbox, three match-failure-to-stage) become `<Quiz>` ([spec 0004](0004-quiz-component.md)), with right/wrong feedback in the style of Part 1. "While you build: three predictions" stays a plain list of prompts to answer in a notes file before reaching the matching Part.
- **Callouts** ("Safety note", "Effect v4") are blockquotes, like Part 1's "Not a sandbox".
- **Sources**: the lesson's "Primary source" (Anthropic's _Scaling Managed Agents_) joins the Sources list at the bottom, marked as the one to read first.
- **Cut**: the lesson-pack scaffolding (navigation, glossary and reference links), and the "swap modules" paragraph, which shrinks to one sentence: the map is a plan, not a contract.

### Claims checked before publishing

- The "~8 tokens/s on a 16 GB M1" figure is not backed by any measurement in the Series, so the Post keeps the point qualitatively (a non-streaming reply can sit silent for tens of seconds on a small laptop) unless Vlad has a measurement to cite.
- OpenCode references (file paths, the quoted `AGENTS.md` rule about "no in-memory tool loop", the `Effect.fork` → `forkChild` rename) link to GitHub at the same pinned commit as Part 1 (`863ea41364`), and each path and quote is checked to exist there. If one does not, the Post moves to a newer commit and says so.
- The five Stage A titles and Part numbers match the Series file exactly.

## User stories

1. As a reader who finished Part 1, I want the five ways its agent breaks named, so I know what the rest of the Series is for.
2. As a reader, I want one framing (Harness, Session, Sandbox) that tells me which part of an agent any piece of code belongs to, and which failure it prevents.
3. As a reader, I want the order of the coming Parts and the reason for it, so a Part that seems unmotivated has an explanation.
4. As a reader, I want to check myself with quizzes and write down predictions before the matching Part, so I remember more of it.
5. As a reader following along, I want the Post not to claim a Part is done or next when it is not.
6. As the author, I want the roadmap to stay accurate as I reorder Parts, without the Post making promises about Stage B and C that I have not scheduled.

## Out of scope

Stage B and Stage C Parts in the Series' Planned Parts, the lesson's reference pages (agent architecture, glossary), an agentic-AI glossary, new components, any change to Part 1.

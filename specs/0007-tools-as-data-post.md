## Problem statement

Part 1 ends with an agent that crashes when a tool throws, and Part 2 promises that _Tools as data_ (Part 3) fixes it. Vlad finished that Part as a lesson in his OpenCode fork (`lessons/0003-tools-as-data.html`, generated by another Claude session), with the code tagged in the Companion repo as `Part3_tools_as_data`. It needed to become Part 3, reading and looking like Parts 1 and 2.

Two things on the blog were out of step with it:

- The Series' `planned` list still contained "The roadmap", already published as Part 2, so the Series page showed it a second time as a Planned Part 3.
- Part 2's Stage C "Permissions" bullet said that stage ends with a y/n prompt before `write_file` and `bash`, which Part 3 builds.

## Solution

A faithful port of the lesson as one Post, lightly edited for the blog, with the same edits as spec 0006. It was a Draft until Vlad had read it, and is now published.

- **Front matter**: category Agentic AI, tags `agents`, `tools`, `typescript`, `ollama`, Series _Building an agent from scratch_, Part 3, Snapshot `Part3_tools_as_data`. The Foreword links to the Snapshot in a plain sentence, like Part 1's ([spec 0005](0005-companion-repo.md)).
- **Content**: the prediction from Part 2 and its answer (an error result on each protocol; the text is the only signal on the OpenAI protocol); a tool as one object (name, description, input schema, executor) compared with Thorsten Ball's Go agent and OpenCode's `read` tool; three rules for tools a model can use well; tools on each provider; seven quizzes; the hands-on build of the registry in six steps on Ollama, then the optional Claude changes; callouts; Sources with the primary source first.
- **Vocabulary**: "Part", not "post", "module" or "lesson". Other Parts are italic titles with their number, unlinked; Part 2 is linked. Agent vocabulary (registry, executor, tool result) is defined inline; `GLOSSARY.md` does not change.
- **Quizzes**: five on this Part and two "From Part 2" sorting a tool object's pieces into Harness, Session or Sandbox, as `<Quiz>` ([spec 0004](0004-quiz-component.md)).
- **Cut**: the lesson-pack scaffolding (navigation, reference and glossary links, the kicker) and the "ask Claude" paragraph.
- **Series**: "The roadmap" and "Tools as data" left `planned`, so the Series page shows Parts 1–3 written and Parts 4–7 planned.
- **Part 2**: one sentence in the Stage C "Permissions" bullet changed so it no longer promises the y/n prompt Part 3 builds; Permissions is now about rules for what may run, replacing Part 3's blanket prompt. Nothing else in Part 2 changed, and Part 1 is untouched.

### Claims

The Post states only what was checked on 2026-11-04: OpenCode links and quotations at the pinned commit `863ea41364` (OpenCode's `read` description is eight sentences, not the lesson's seven); the Claude, Ollama and llama.cpp doc quotations and Anthropic's tool-design post; every code block against Part 1's finished files; both finished files type-check, and the three `runTool` failures print as shown.

## User stories

1. As a reader who finished Part 2, I want the crash from Part 1 fixed, so I can see a failing tool become something the model reads and acts on.
2. As a reader, I want to recall my prediction before seeing the answer, so I remember it better.
3. As a reader, I want a tool to be one object that both protocols derive their format from, so adding a tool never touches the loop or the protocol code.
4. As a reader, I want to know what makes a tool description or error message good enough for a small local model, not just for Claude.
5. As a reader following along, I want each build step to end with something to run, and a finished file to compare with when I'm stuck.
6. As a reader who ran Part 1, I want the Claude changes kept optional and separate, so I can skip them.
7. As a reader, I want the code as it stood when the Part was written, through the Snapshot link.
8. As a reader of the Series page, I want the list of Parts to show each Part once, in order.
9. As a reader of Part 2, I want its Stage C description not to promise what Part 3 already did.

## Out of scope

The lesson's reference pages (tool design, agent architecture, glossary), an agentic-AI glossary, new components, Stage B and Stage C Parts in the Series' Planned Parts, any change to Part 1, any change to Part 2 beyond the one sentence.

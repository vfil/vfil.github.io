## Foreword

This Part rewrites the agent from [Part 4](/posts/providers-behind-one-interface/) so that every failure shows in a type: tools fail with typed errors, a Schema validates each tool's input, and the errors the model reads are kept apart from the errors the user reads. The code also moves from one file to eight. It is the third Part of Stage A (Harness) in [the roadmap](/posts/the-roadmap/).

The code for this Part is available as the [`Part5_use_effects` snapshot of vfil/sigma-agent](https://github.com/vfil/sigma-agent/tree/Part5_use_effects), the repo where I build this agent in parallel.

## Start from the failures

The agent from [Part 4](/posts/providers-behind-one-interface/) has four kinds of failure, and the code handles each of them differently. None of the four shows in a type.

| Failure                                                                                              | Where it is raised | What happens in Part 4                                                                                         |
| ---------------------------------------------------------------------------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------- |
| A tool is unknown, its input is wrong, the user declines, or the tool's code throws                  | Inside `runTool`   | The `catch` turns it into an error result and the model reads it                                               |
| A bug in the agent's own code that runs inside that `try` block, for example in a `confirm` function | Inside `runTool`   | The same `catch` turns it into an error result. The model is told about a mistake that only the author can fix |
| The model request fails: server not running, a 404, a reply that cannot be read                      | `chat`             | The error is thrown out of the loop and the program exits                                                      |
| Input ends, from piped input or Ctrl-D                                                               | `rl.question`      | The call throws `readline was closed`, or, when input ends during a question, never returns                    |

The first row works because [Part 3](/posts/tools-as-data/) put one `try`/`catch` around the whole call. The other rows show what that does not express. TypeScript does not distinguish a failure the model can fix from a bug, or from a failure that only the user can fix, and a function's type does not say whether it can throw at all. [Part 1](/posts/the-loop/) already ran into the last point. Pointing `list_files` at a directory that does not exist ended the program:

```ts
import { readdir } from "node:fs/promises"

const listFiles = async (path: string) => {
  const entries = await readdir(path, { withFileTypes: true })
  return entries.map((entry) => (entry.isDirectory() ? `${entry.name}/` : entry.name)).join("\n")
}

console.log(await listFiles("missing"))
```

```text
$ cd playground && bun ../plain.ts
4 |   const entries = await readdir(path, { withFileTypes: true })
                            ^
ENOENT: no such file or directory, scandir 'missing'
    path: "missing",

   errno: -2,
    code: "ENOENT"
```

The type of `listFiles` is `(path: string) => Promise<string>`. Nothing in it mentions `ENOENT`. This Part moves the agent to Effect, a library whose central idea is to put the failure into the type.

## What Effect adds

Effect's own introduction, [Why Effect?](https://effect.website/docs/getting-started/why-effect/), makes the same observation about a plain `divide` function: "Based on the types, we have no idea that this function can throw an exception." Its core claim is that "we can use the type system to track errors and context, not only success values." The page is part of the v3 documentation, and OpenCode uses v4, so some names differ; the [v3 to v4 migration guide](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md) lists them. The snippets in this Part were run on Effect 4.1.0, the version OpenCode pins at the commit its links point to (`97be25f046`).

This section covers the four ideas the rest of this Part uses. Each snippet was run on its own before it went into this Part.

### 1. An Effect is a value with three type parameters

`Effect<A, E, R>` describes a computation that produces an `A`, can fail with an `E`, and needs an `R` to run. `R` stands for requirements such as services. It stays `never` (nothing is required) in this Part, and _Services and layers_ (Part 6) uses it. Here `listFiles` is written again, with the failure as a class. `Schema.TaggedError` defines a class whose instances carry a `_tag` that names the failure, and Schema gives its fields their types. (A `_tag` is Effect vocabulary and has nothing to do with the Tags of a Post on this blog.)

```ts
import { Effect, Schema } from "effect"
import { readdir } from "node:fs/promises"

class NotListable extends Schema.TaggedError<NotListable>()("NotListable", {
  path: Schema.String,
  reason: Schema.String,
}) {}

const listFiles = (path: string) =>
  Effect.tryPromise({
    try: () => readdir(path, { withFileTypes: true }),
    catch: (error) => new NotListable({ path, reason: error instanceof Error ? error.message : String(error) }),
  }).pipe(Effect.map((entries) => entries.map((entry) => (entry.isDirectory() ? `${entry.name}/` : entry.name)).join("\n")))
```

`Effect.tryPromise` runs a function that returns a promise, and `catch` turns whatever it rejects with into the typed failure. The type of `listFiles` is now `(path: string) => Effect<string, NotListable, never>`: it produces a string, can fail with `NotListable`, and requires nothing. The compiler enforces this. Assigning the result to an Effect that cannot fail is an error:

```ts
const sure: Effect.Effect<string> = listFiles("missing")
```

```text
$ bunx --package typescript tsc --noEmit
effect2.ts(4,7): error TS2322: Type 'Effect<string, NotListable, never>' is not assignable to type 'Effect<string, never, never>'.
  Type 'NotListable' is not assignable to type 'never'.
```

### 2. `Effect.gen` and `yield*` play the role of `async` and `await`

Inside `Effect.gen`, `yield*` runs another Effect and gives back its success value. If that Effect fails, the generator stops and the Effect it belongs to fails with the same error:

```ts
const listBoth = Effect.gen(function* () {
  console.log("listing")
  const here = yield* listFiles(".")
  const notes = yield* listFiles("notes")
  return `${here}\n${notes}`
})
// listBoth: Effect<string, NotListable, never>
```

The error types of the steps are combined, so `listBoth` has the same `NotListable` in its type without anyone writing it down. With `async` functions this information is lost at every `await`.

### 3. An Effect describes work and does nothing until it is run

Building `listBoth` does not list any directory. The work starts when the Effect is run, and a program does that once, at its edge. `Effect.runPromise` is the usual way:

```ts
console.log("built the Effect")
console.log(await Effect.runPromise(listBoth))
```

```text
$ cd playground && bun ../effect3.ts
built the Effect
listing
secret-file.txt
README.md
notes/
todo.txt
```

`listing` prints after `built the Effect`. An Effect that is created and never yielded or run does nothing, and the compiler does not report it. A missing `yield*` is a mistake to look for when a step seems to be skipped.

### 4. A failure is handled by its type, and the type shrinks

`Effect.catch` takes a handler for the typed failure. After it, `E` is `never`, and the earlier compiler error disappears:

```ts
const safe = listFiles("missing").pipe(
  Effect.catch((error) => Effect.succeed(`Could not list ${error.path}: ${error.reason}`)),
)
const sure: Effect.Effect<string> = safe

console.log(await Effect.runPromise(safe))
```

```text
$ cd playground && bun ../effect4.ts
Could not list missing: ENOENT: no such file or directory, scandir 'missing'
```

There is a second kind of failure that `Effect.catch` does not see. A **defect** is an error nobody planned for, such as an exception thrown by a bug. It is not part of `E`, it passes through `Effect.catch`, and it has its own handler, `Effect.catchDefect`. The agent uses this difference to keep bugs away from the model.

## Five decisions in the rewrite

### 1. A tool failure is a typed class

A **tool failure** is a typed error raised while running a tool call, and the agent turns it into an error tool result. The agent has four, each with the fields that describe it and a `message` that becomes the text the model reads:

| Failure        | Raised when                                                                                 | What the model reads                                           |
| -------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `UnknownTool`  | The call names a tool that is not registered                                                | `Unknown tool: x. Available tools: list_files, read_file, …`   |
| `InvalidInput` | The arguments are not valid JSON, or do not fit the tool's Schema                           | Each problem, then the fields the tool takes                   |
| `Declined`     | The user answers anything but `y`, or there is no answer                                    | `User declined this action. Ask what they would like instead.` |
| `ToolCrashed`  | The tool's own code throws or rejects: a missing file, a bad edit, a command that timed out | The error's message, as in Part 3                              |

Part 4 had these messages as strings in four places. Now each is a class, and a function that can raise one has it in its type.

### 2. One place turns a failure into a result

Each tool's `run` has the type `Effect<string, ToolFailure>`, where `ToolFailure` is the union of the four classes. `runTool` runs it and converts both outcomes into the same result type as in Part 4: a string becomes `{ type: "text" }` and a failure becomes `{ type: "error" }`. Its return type is `Effect<ToolResultPart>`, which is `Effect<ToolResultPart, never, never>` with the defaults left out. The protocols are unchanged, because they only ever see a tool result.

The union is checked. If `run` is changed so that it can fail with something that is not in `ToolFailure`, for example a `ProviderError`, the compiler reports it where the `Tool` is built, before anything runs:

```text
src/tool.ts(34,7): error TS2322: Type 'Effect<string, Declined | InvalidInput | ProviderError | ToolCrashed, S["DecodingServices"]>' is not assignable to type 'Effect<string, ToolFailure, never>'.
```

### 3. Expected failures and defects are separate

`runTool` handles the typed failures only. A bug inside the agent, such as a function that throws while describing a confirmation, is a defect. It is not converted into a tool result. OpenCode draws the same line. The comment on its `ToolFailure` says that handlers must map their errors to it, and that the runtime surfaces those as an error result "so the model can self-correct". It continues: "Anything thrown or yielded by a handler that is not a `ToolFailure` is treated as a defect and fails the stream" ([schema/errors.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/ai/src/schema/errors.ts)). Its tool guidelines add that interruption and defects must survive, so they do not use `catchCause` there ([tool/AGENTS.md](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/tool/AGENTS.md)).

### 4. Provider errors reach the user, and the turn is dropped

A failed model request is not something the model can act on. `chat` now fails with a `ProviderError` that carries the status and body, or says that the server could not be reached or its reply could not be read. The prompt loop catches it, together with defects, prints it, and returns to `You:`.

The turn that failed is removed from the history. A turn can fail after the model asked for tools and before their results were added, and a history that ends with a tool call and no result is not valid for either protocol (Part 3: every call needs its own result). Cutting the history back to its length before the prompt keeps the next prompt on a consistent conversation.

### 5. One Schema describes a tool's input

In Part 4 a tool's input was described twice: a JSON Schema object for the model and `field()` calls for validation. They could drift apart. Now each tool declares one `Schema.Struct`. `Schema.decodeUnknownEffect` validates the model's arguments against it, and `Schema.toJsonSchemaDocument` produces the JSON Schema that goes into the request. OpenCode uses both functions for the same two jobs in [ai/src/tool.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/ai/src/tool.ts).

Schema's default messages for a wrong input are short. For `{}` and for `{ path: 42 }` against a Schema with a `path` string field they are:

```text
Missing key
  at ["path"]

Expected string
  at ["path"]
```

Part 3 gave the model `path must be a string, e.g. src/index.ts`, which names the field and says what to send. The default text names the field and the problem, and leaves out what the tool takes. `InvalidInput` lists every problem as `field: problem` and then names the fields the tool takes, which is the purpose Part 3's message served. Step 6 shows a model correcting a call from it.

```ts
// The agent (Part 5)
type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema
  run: (input: unknown) => Effect.Effect<string, ToolFailure>
}
```

```ts
// OpenCode (ai/src/tool.ts, abridged)
interface Tool<Input, Success> {
  readonly name: string
  readonly description: string
  readonly input: Input // an Effect Schema
  readonly success: Success // an Effect Schema
  readonly execute?: ToolExecute<Input, Success>
  // memoized codecs, a precomputed definition, ...
}

type ToolExecute<Input, Success> = (
  input: ToolInputType<Input>,
  context?: ToolExecuteContext,
) => Effect.Effect<Schema.Schema.Type<Success>, ToolFailure>
```

The agent keeps the Schema inside the tool. `defineTool` takes a typed `execute` and builds a `run` that decodes the raw input, asks for confirmation and calls `execute`. That makes the registry a plain `Tool[]` whatever the tools' input types are. OpenCode's tool object carries the Schema and a decoder for it, and its `execute` receives the decoded input. It also has a second Schema for the output. Its tool guidelines state that the registry erases the definitions' types at that boundary ([tool/AGENTS.md](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/tool/AGENTS.md)).

```ts
// The agent's own message types. No protocol appears in them.
export type TextPart = { type: "text"; text: string }
export type ToolCallPart = { type: "tool-call"; id: string; name: string; input: unknown }
export type ToolResultValue = { type: "text" | "error"; value: string }
export type ToolResultPart = { type: "tool-result"; id: string; name: string; result: ToolResultValue }
export type Part = TextPart | ToolCallPart | ToolResultPart

export type Message = {
  role: "user" | "assistant" | "tool"
  content: Part[]
  // The provider's own content for this message, kept so the same protocol can send it back unchanged.
  native?: unknown
}

export const isToolCall = (part: Part): part is ToolCallPart => part.type === "tool-call"
export const textOf = (message: Message) => message.content.flatMap((part) => (part.type === "text" ? [part.text] : [])).join("\n")
```

```ts
import type { ToolCallPart, ToolResultPart, ToolResultValue } from "./messages"
import { rl } from "./terminal"

export type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema, shared by both protocols
  execute: (input: unknown) => Promise<string>
  confirm?: (input: unknown) => string // describes the action; when set, the user must approve it first
}

// Reads one string field from model input, or throws a message that says how to fix it.
export const field = (input: unknown, key: string, example: string): string => {
  const value = typeof input === "object" && input !== null ? (input as Record<string, unknown>)[key] : undefined
  if (typeof value !== "string") throw new Error(`${key} must be a string, e.g. ${example}`)
  return value
}

// Never throws: every failure becomes a tool result the model can read.
export const runTool = async (tools: Tool[], call: ToolCallPart): Promise<ToolResultPart> => {
  const done = (result: ToolResultValue): ToolResultPart => ({ type: "tool-result", id: call.id, name: call.name, result })

  try {
    const tool = tools.find((tool) => tool.name === call.name)
    if (!tool) throw new Error(`Unknown tool: ${call.name}. Available tools: ${tools.map((tool) => tool.name).join(", ")}`)

    // A string input is arguments that were not valid JSON; the protocol keeps the raw text.
    if (typeof call.input === "string") throw new Error(`The arguments are not valid JSON: ${call.input}`)

    if (tool.confirm) {
      const answer = await rl.question(`Allow: ${tool.confirm(call.input)}? [y/N] `)
      if (answer.trim().toLowerCase() !== "y") throw new Error("User declined this action. Ask what they would like instead.")
    }
    return done({ type: "text", value: await tool.execute(call.input) })
  } catch (error) {
    return done({ type: "error", value: error instanceof Error ? error.message : String(error) })
  }
}
```

```ts
  if (oldStr === newStr) throw new Error("old_str and new_str must be different")

  if (oldStr === "") {
```

```ts
// A protocol turns the agent's types into one wire format and back.
export type Protocol = {
  path: string
  body: (model: string, history: Message[], tools: Tool[]) => unknown
  decode: (json: unknown) => Reply
}

// OpenAI Chat Completions: what Ollama and llama.cpp speak. Only this section knows its wire format.
type OpenAIResponse = {
  choices: { message: { content: string | null; tool_calls?: { id: string; function: { name: string; arguments: string } }[] } }[]
}

const toOpenAITool = (tool: Tool) => ({
  type: "function",
  function: { name: tool.name, description: tool.description, parameters: tool.parameters },
})

const toOpenAIMessages = (message: Message): unknown[] => {
  if (message.role === "tool") {
    // One role: "tool" message per result. There is no error flag, so the text carries the failure.
    return message.content.flatMap((part) =>
      part.type === "tool-result"
        ? [{ role: "tool", tool_call_id: part.id, content: part.result.type === "error" ? `Error: ${part.result.value}` : part.result.value }]
        : [],
    )
  }
  if (message.role === "assistant") {
    const calls = message.content.filter(isToolCall).map((call) => ({
      id: call.id,
      type: "function",
      // A string input is raw text that did not parse; send it back as it came.
      function: { name: call.name, arguments: typeof call.input === "string" ? call.input : JSON.stringify(call.input) },
    }))
    return [{ role: "assistant", content: textOf(message) || null, ...(calls.length ? { tool_calls: calls } : {}) }]
  }
  return [{ role: "user", content: textOf(message) }]
}

// Arguments arrive as a JSON string. If it does not parse, keep the raw text as the input.
const parseArguments = (raw: string): unknown => {
  try {
    return JSON.parse(raw)
  } catch {
    return raw
  }
}

export const openaiChat: Protocol = {
  path: "/chat/completions",
  body: (model, history, tools) => ({
    model,
    messages: history.flatMap(toOpenAIMessages),
    reasoning_effort: "none",
    tools: tools.map(toOpenAITool),
  }),
  decode: (json) => {
    const message = (json as OpenAIResponse).choices[0]?.message
    if (!message) throw new Error("No choices returned from model")
    const content: Part[] = []
    if (message.content) content.push({ type: "text", text: message.content })
    for (const call of message.tool_calls ?? []) {
      content.push({ type: "tool-call", id: call.id, name: call.function.name, input: parseArguments(call.function.arguments) })
    }
    return { message: { role: "assistant", content }, finish: content.some(isToolCall) ? "tool-calls" : "stop" }
  },
}

// Anthropic Messages: what Claude speaks.
type AnthropicText = { type: "text"; text: string }
type AnthropicToolUse = { type: "tool_use"; id: string; name: string; input: unknown }
type AnthropicBlock = AnthropicText | AnthropicToolUse | { type: string } // e.g. thinking blocks
type AnthropicResponse = { content: AnthropicBlock[]; stop_reason: string }

const isText = (block: AnthropicBlock): block is AnthropicText => block.type === "text"
const isToolUse = (block: AnthropicBlock): block is AnthropicToolUse => block.type === "tool_use"

// Same name and description as every other tool, but the schema is called input_schema.
const toAnthropicTool = (tool: Tool) => ({ name: tool.name, description: tool.description, input_schema: tool.parameters })

const toAnthropicMessage = (message: Message): unknown => {
  if (message.role === "tool") {
    // All the results of a step go back in one user message, and failures carry is_error.
    return {
      role: "user",
      content: message.content.flatMap((part) =>
        part.type === "tool-result"
          ? [{ type: "tool_result", tool_use_id: part.id, content: part.result.value, is_error: part.result.type === "error" }]
          : [],
      ),
    }
  }
  if (message.role === "assistant") {
    // Send back exactly what the model produced, thinking blocks included, when we kept it.
    if (message.native) return { role: "assistant", content: message.native }
    return {
      role: "assistant",
      content: message.content.flatMap((part): unknown[] =>
        part.type === "text"
          ? [{ type: "text", text: part.text }]
          : part.type === "tool-call"
            ? [{ type: "tool_use", id: part.id, name: part.name, input: part.input }]
            : [],
      ),
    }
  }
  return { role: "user", content: textOf(message) }
}

  path: "/v1/messages",

    model,
    max_tokens: 16000,

    tools: tools.map(toAnthropicTool),

    const data = json as AnthropicResponse
    const content: Part[] = []
    for (const block of data.content) {
      if (isText(block)) content.push({ type: "text", text: block.text })
      else if (isToolUse(block)) content.push({ type: "tool-call", id: block.id, name: block.name, input: block.input })
    }
    const finish = data.stop_reason === "refusal" ? "refusal" : content.some(isToolCall) ? "tool-calls" : "stop"
```

This file changes the most. `Tool` loses `execute` and `confirm` and gets `run`, the JSON Schema is derived instead of written, and `field` is gone. ```ts

`defineTool` builds a `Tool` from a Schema. Its generic parameter `S` carries the input type to `execute` and `confirm`, and `DecodingServices: never` limits `S` to Schemas that need nothing else to decode, which is what keeps `R` at `never`. `takes` is the list of field names, `decode` is the validator, and `parameters` is the JSON Schema derived from the same Schema.

`run` is an `Effect.gen` with four steps: reject text that was not JSON, decode the input, ask for confirmation, run the tool. Each `return yield* new …` stops the generator with that failure, the way a `throw` would. Three calls bring in errors from outside the agent: `mapError` turns Schema's error into `InvalidInput`, `orElseSucceed` makes an input that ended count as an empty answer, and `tryPromise` turns a rejected promise into `ToolCrashed`:

```ts
// Builds a Tool from one Schema: it validates the input and produces the JSON Schema the model receives.
// `DecodingServices: never` limits S to Schemas that need nothing else to decode, so `run` keeps R = never.
export const defineTool = <S extends Schema.Struct<Schema.Struct.Fields> & { readonly DecodingServices: never }>(config: {
  name: string
  description: string
  input: S
  execute: (input: S["Type"]) => Promise<string>
  confirm?: (input: S["Type"]) => string // describes the action; when set, the user must approve it first
}): Tool => {
  const takes = Object.keys(config.input.fields).join(", ")
  const decode = Schema.decodeUnknownEffect(config.input)

  return {
    name: config.name,
    description: config.description,
    parameters: Schema.toJsonSchemaDocument(config.input).schema,
    run: (raw) =>
      Effect.gen(function* () {
        // A string is arguments that were not valid JSON; the protocol keeps the raw text.
        if (typeof raw === "string") {
          return yield* new InvalidInput({ tool: config.name, problems: [`the arguments are not valid JSON: ${raw}`], takes })
        }

        const input = yield* decode(raw, { errors: "all" }).pipe(
          Effect.mapError(
            (error) =>
              new InvalidInput({
                tool: config.name,
                problems: formatIssues(error.issue).issues.map((issue) => `${issue.path?.join(".") || "input"}: ${issue.message}`),
                takes,
              }),
          ),
        )

        if (config.confirm) {
          // No answer counts as "no".
          const answer = yield* ask(`Allow: ${config.confirm(input)}? [y/N] `).pipe(Effect.orElseSucceed(() => ""))
          if (answer.trim().toLowerCase() !== "y") return yield* new Declined()
        }

        return yield* Effect.tryPromise({
          try: () => config.execute(input),
          catch: (error) => new ToolCrashed({ tool: config.name, reason: messageOf(error) }),
        })
      }),
  }
}
```

```ts
        if (typeof raw === "string") {
          return yield* new InvalidInput({ tool: config.name, problems: [`the arguments are not valid JSON: ${raw}`], takes })
        }

        const input = yield* decode(raw, { errors: "all" }).pipe(
          Effect.mapError(
            (error) =>
              new InvalidInput({
                tool: config.name,
                problems: formatIssues(error.issue).issues.map((issue) => `${issue.path?.join(".") || "input"}: ${issue.message}`),
                takes,
              }),
          ),
        )

        if (config.confirm) {
          // No answer counts as "no".
          const answer = yield* ask(`Allow: ${config.confirm(input)}? [y/N] `).pipe(Effect.orElseSucceed(() => ""))
          if (answer.trim().toLowerCase() !== "y") return yield* new Declined()
        }

        return yield* Effect.tryPromise({
          try: () => config.execute(input),
          catch: (error) => new ToolCrashed({ tool: config.name, reason: messageOf(error) }),
        })
      }),
  }
}

// Cannot fail: every tool failure becomes a tool result the model can read.
export const runTool = (tools: Tool[], call: ToolCallPart): Effect.Effect<ToolResultPart> => {
  const done = (result: ToolResultValue): ToolResultPart => ({ type: "tool-result", id: call.id, name: call.name, result })
  const tool = tools.find((tool) => tool.name === call.name)
  const run = tool ? tool.run(call.input) : Effect.fail(new UnknownTool({ name: call.name, available: tools.map((tool) => tool.name) }))

  return run.pipe(
    Effect.map((value) => done({ type: "text", value })),
    Effect.catch((failure) => Effect.succeed(done({ type: "error", value: failure.message }))),
  )
}
```

> **Watch for this.** `Effect.catch` and `catchTag` handle typed failures only. A bug that throws is a defect, and the typed handler next to it does not run for it. When a handler seems to be ignored, check which of the two kinds of failure reached it.

> **Result.** In this agent every function that can fail has the failure in its type. The model reads tool failures, the user reads provider errors and bugs, and a failed turn leaves the history valid. A new tool is one `defineTool` entry, and a new route or protocol changes neither the tools nor the loop.

```ts
import { Effect, Schema, SchemaIssue } from "effect"
import { Declined, InvalidInput, messageOf, ToolCrashed, UnknownTool } from "./errors"
import type { ToolCallPart, ToolResultPart, ToolResultValue } from "./messages"
import { ask } from "./terminal"

export type ToolFailure = UnknownTool | InvalidInput | Declined | ToolCrashed

export type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema, derived from the input Schema
  run: (input: unknown) => Effect.Effect<string, ToolFailure>
}

const formatIssues = SchemaIssue.makeFormatterStandardSchemaV1()

// Builds a Tool from one Schema: it validates the input and produces the JSON Schema the model receives.
// `DecodingServices: never` limits S to Schemas that need nothing else to decode, so `run` keeps R = never.
export const defineTool = <S extends Schema.Struct<Schema.Struct.Fields> & { readonly DecodingServices: never }>(config: {
  name: string
  description: string
  input: S
  execute: (input: S["Type"]) => Promise<string>
  confirm?: (input: S["Type"]) => string // describes the action; when set, the user must approve it first
}): Tool => {
  const takes = Object.keys(config.input.fields).join(", ")
  const decode = Schema.decodeUnknownEffect(config.input)

  return {
    name: config.name,
    description: config.description,
    parameters: Schema.toJsonSchemaDocument(config.input).schema,
    run: (raw) =>
      Effect.gen(function* () {
        // A string is arguments that were not valid JSON; the protocol keeps the raw text.
        if (typeof raw === "string") {
          return yield* new InvalidInput({ tool: config.name, problems: [`the arguments are not valid JSON: ${raw}`], takes })
        }

        const input = yield* decode(raw, { errors: "all" }).pipe(
          Effect.mapError(
            (error) =>
              new InvalidInput({
                tool: config.name,
                problems: formatIssues(error.issue).issues.map((issue) => `${issue.path?.join(".") || "input"}: ${issue.message}`),
                takes,
              }),
          ),
        )

        if (config.confirm) {
          // No answer counts as "no".
          const answer = yield* ask(`Allow: ${config.confirm(input)}? [y/N] `).pipe(Effect.orElseSucceed(() => ""))
          if (answer.trim().toLowerCase() !== "y") return yield* new Declined()
        }

        return yield* Effect.tryPromise({
          try: () => config.execute(input),
          catch: (error) => new ToolCrashed({ tool: config.name, reason: messageOf(error) }),
        })
      }),
  }
}

// Cannot fail: every tool failure becomes a tool result the model can read.
export const runTool = (tools: Tool[], call: ToolCallPart): Effect.Effect<ToolResultPart> => {
  const done = (result: ToolResultValue): ToolResultPart => ({ type: "tool-result", id: call.id, name: call.name, result })
  const tool = tools.find((tool) => tool.name === call.name)
  const run = tool ? tool.run(call.input) : Effect.fail(new UnknownTool({ name: call.name, available: tools.map((tool) => tool.name) }))

  return run.pipe(
    Effect.map((value) => done({ type: "text", value })),
    Effect.catch((failure) => Effect.succeed(done({ type: "error", value: failure.message }))),
  )
}
```

```ts
  if (oldStr === newStr) throw new Error("old_str and new_str must be different")

  if (oldStr === "") {
    if (existsSync(path)) throw new Error(`${path} already exists; pass the text to replace as old_str`)
    await mkdir(dirname(path), { recursive: true })
    await writeFile(path, newStr)
    return `Created ${path}`
  }

  const content = await readFile(path, "utf8")
  const matches = content.split(oldStr).length - 1
  if (matches === 0) throw new Error(`old_str was not found in ${path}`)
  if (matches > 1) throw new Error(`old_str matches ${matches} places in ${path}; include more surrounding text`)
  await writeFile(path, content.replace(oldStr, () => newStr))
  return "OK"
}
```

```ts
import { isToolCall, textOf, type Message, type Part } from "./messages"
import type { Tool } from "./tool"

export type Reply = { message: Message; finish: "tool-calls" | "stop" | "refusal" }

// A protocol turns the agent's types into one wire format and back.
export type Protocol = {
  path: string
  body: (model: string, history: Message[], tools: Tool[]) => unknown
  decode: (json: unknown) => Reply
}

// OpenAI Chat Completions: what Ollama and llama.cpp speak. Only this section knows its wire format.
type OpenAIResponse = {
  choices: { message: { content: string | null; tool_calls?: { id: string; function: { name: string; arguments: string } }[] } }[]
}

const toOpenAITool = (tool: Tool) => ({
  type: "function",
  function: { name: tool.name, description: tool.description, parameters: tool.parameters },
})

const toOpenAIMessages = (message: Message): unknown[] => {
  if (message.role === "tool") {
    // One role: "tool" message per result. There is no error flag, so the text carries the failure.
    return message.content.flatMap((part) =>
      part.type === "tool-result"
        ? [{ role: "tool", tool_call_id: part.id, content: part.result.type === "error" ? `Error: ${part.result.value}` : part.result.value }]
        : [],
    )
  }
  if (message.role === "assistant") {
    const calls = message.content.filter(isToolCall).map((call) => ({
      id: call.id,
      type: "function",
      // A string input is raw text that did not parse; send it back as it came.
      function: { name: call.name, arguments: typeof call.input === "string" ? call.input : JSON.stringify(call.input) },
    }))
    return [{ role: "assistant", content: textOf(message) || null, ...(calls.length ? { tool_calls: calls } : {}) }]
  }
  return [{ role: "user", content: textOf(message) }]
}

// Arguments arrive as a JSON string. If it does not parse, keep the raw text as the input.
const parseArguments = (raw: string): unknown => {
  try {
    return JSON.parse(raw)
  } catch {
    return raw
  }
}

export const openaiChat: Protocol = {
  path: "/chat/completions",
  body: (model, history, tools) => ({
    model,
    messages: history.flatMap(toOpenAIMessages),
    reasoning_effort: "none",
    tools: tools.map(toOpenAITool),
  }),
  decode: (json) => {
    const message = (json as OpenAIResponse).choices[0]?.message
    if (!message) throw new Error("No choices returned from model")
    const content: Part[] = []
    if (message.content) content.push({ type: "text", text: message.content })
    for (const call of message.tool_calls ?? []) {
      content.push({ type: "tool-call", id: call.id, name: call.function.name, input: parseArguments(call.function.arguments) })
    }
    return { message: { role: "assistant", content }, finish: content.some(isToolCall) ? "tool-calls" : "stop" }
  },
}

// Anthropic Messages: what Claude speaks.
type AnthropicText = { type: "text"; text: string }
type AnthropicToolUse = { type: "tool_use"; id: string; name: string; input: unknown }
type AnthropicBlock = AnthropicText | AnthropicToolUse | { type: string } // e.g. thinking blocks
type AnthropicResponse = { content: AnthropicBlock[]; stop_reason: string }

const isText = (block: AnthropicBlock): block is AnthropicText => block.type === "text"
const isToolUse = (block: AnthropicBlock): block is AnthropicToolUse => block.type === "tool_use"

// Same name and description as every other tool, but the schema is called input_schema.
const toAnthropicTool = (tool: Tool) => ({ name: tool.name, description: tool.description, input_schema: tool.parameters })

const toAnthropicMessage = (message: Message): unknown => {
  if (message.role === "tool") {
    // All the results of a step go back in one user message, and failures carry is_error.
    return {
      role: "user",
      content: message.content.flatMap((part) =>
        part.type === "tool-result"
          ? [{ type: "tool_result", tool_use_id: part.id, content: part.result.value, is_error: part.result.type === "error" }]
          : [],
      ),
    }
  }
  if (message.role === "assistant") {
    // Send back exactly what the model produced, thinking blocks included, when we kept it.
    if (message.native) return { role: "assistant", content: message.native }
    return {
      role: "assistant",
      content: message.content.flatMap((part): unknown[] =>
        part.type === "text"
          ? [{ type: "text", text: part.text }]
          : part.type === "tool-call"
            ? [{ type: "tool_use", id: part.id, name: part.name, input: part.input }]
            : [],
      ),
    }
  }
  return { role: "user", content: textOf(message) }
}

export const anthropicMessages: Protocol = {
  path: "/v1/messages",
  body: (model, history, tools) => ({
    model,
    max_tokens: 16000,
    messages: history.map(toAnthropicMessage),
    tools: tools.map(toAnthropicTool),
  }),
  decode: (json) => {
    const data = json as AnthropicResponse
    const content: Part[] = []
    for (const block of data.content) {
      if (isText(block)) content.push({ type: "text", text: block.text })
      else if (isToolUse(block)) content.push({ type: "tool-call", id: block.id, name: block.name, input: block.input })
    }
    const finish = data.stop_reason === "refusal" ? "refusal" : content.some(isToolCall) ? "tool-calls" : "stop"
    return { message: { role: "assistant", content, native: data.content }, finish }
  },
}
```

```ts
  model: process.env.MODEL ?? selected.model,

// One step: one model call. It fails with a ProviderError that the user reads; the model never sees it.
export const chat = (history: Message[], tools: Tool[]) =>
  Effect.gen(function* () {
    const unreachable = (error: unknown) => new ProviderError({ reason: `Could not reach ${route.baseUrl}: ${messageOf(error)}` })

    const response = yield* Effect.tryPromise({
      try: () =>
        fetch(`${route.baseUrl}${route.protocol.path}`, {
          method: "POST",
          headers: { "content-type": "application/json", ...route.headers },
          body: JSON.stringify(route.protocol.body(route.model, history, tools)),
        }),
      catch: unreachable,
    })
    const text = yield* Effect.tryPromise({ try: () => response.text(), catch: unreachable })
    if (!response.ok) return yield* new ProviderError({ reason: `${route.baseUrl} answered ${response.status}: ${text}` })

    return yield* Effect.try({
      try: (): Reply => route.protocol.decode(JSON.parse(text)),
      catch: (error) => new ProviderError({ reason: `Could not read the reply from ${route.baseUrl}: ${messageOf(error)}` }),
    })
  })
```

```ts
import { Effect } from "effect"
import { messageOf } from "./errors"
import { isToolCall, type Message, type ToolResultPart } from "./messages"
import { chat } from "./provider"
import { ask } from "./terminal"
import { runTool } from "./tool"
import { tools } from "./tools"

const history: Message[] = []

// One prompt: call the model until it stops asking for tools.
const turn = (input: string) =>
  Effect.gen(function* () {
    history.push({ role: "user", content: [{ type: "text", text: input }] })

    while (true) {
      const { message, finish } = yield* chat(history, tools)
      history.push(message)
      for (const part of message.content) {
        if (part.type === "text" && part.text) console.log(`Agent: ${part.text}`)
      }
      if (finish !== "tool-calls") return

      const results: ToolResultPart[] = []
      for (const call of message.content.filter(isToolCall)) {
        console.log(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
        const result = yield* runTool(tools, call)
        if (result.result.type === "error") console.log(`[error] ${result.result.value}`)
        results.push(result)
      }
      history.push({ role: "tool", content: results })
    }
  })

const program = Effect.gen(function* () {
  while (true) {
    const input = yield* ask("You: ")

    // A turn that fails is dropped from the history, so the next prompt starts from a consistent conversation.
    const before = history.length
    const drop = (label: string, reason: string) =>
      Effect.sync(() => {
        history.length = before
        console.log(`[${label}] ${reason}`)
      })

    yield* turn(input).pipe(
      Effect.catchTag("ProviderError", (error) => drop("provider error", error.message)),
      Effect.catchDefect((defect) => drop("bug", messageOf(defect))),
    )
  }
}).pipe(Effect.catchTag("InputClosed", () => Effect.void))

await Effect.runPromise(program)
```

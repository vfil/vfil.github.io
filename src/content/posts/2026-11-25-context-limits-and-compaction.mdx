## Foreword

Every step sends the whole history to the model, and the history only grows. This Part adds a size check before each step. When the next request would come close to the model's limit, the model writes a summary, the agent appends it to the log, and the next step starts from it. This is the third and last Part of Stage B (Session) in [the roadmap](/posts/the-roadmap/).

The code for this Part is available in the repo [https://github.com/vfil/sigma-agent/tree/Part10_context_limit_compaction](https://github.com/vfil/sigma-agent/tree/Part10_context_limit_compaction).

## A session that outgrows the model

Since [Part 8](/posts/the-session-as-an-event-log/), the agent rebuilds the history from the event log before every step and sends all of it. Every prompt, answer and tool result stays in that history for the rest of the session, so a task that reads ten files sends all ten with every later step.

A model can only take in so much at once. That limit is its _context window_: the most tokens it accepts for one step, request and reply together. A _token_ is the unit a model reads text in, usually a word or part of a word. [Part 1](/posts/the-loop/) started both local servers with a 32k window (32,768 tokens). Claude models have much larger windows, so a session reaches the limit later, but a long enough session still reaches it.

### What providers do with a request that is too long

Providers react differently to a request that is too long. The two requests below are plain HTTP calls, with no agent involved. Each sends one user message: a secret word on the first line, a few thousand lines of filler, and a question about the word at the end. The first request goes to a second Ollama server, started with `OLLAMA_HOST=127.0.0.1:11435 OLLAMA_CONTEXT_LENGTH=4096 ollama serve`, and its message is more than twice the configured length:

```text
$ curl -s http://127.0.0.1:11435/v1/chat/completions -H 'content-type: application/json' -d @over-4k.json
{"choices":[{"index":0,"message":{"role":"assistant","content":"PELICAN", ...},"finish_reason":"stop"}],
 "usage":{"prompt_tokens":8724,"completion_tokens":758,"total_tokens":9482}, ...}
```

Ollama answers with status 200 and gives no sign that the request was longer than its configured context. With the MLX runner that Ollama 0.40.18 uses for this model on Apple silicon, the model read the whole message and found the word. Other runners and versions may behave differently, for example by dropping part of the prompt, and in neither case does the response tell the agent that the request was too long.

The second request goes to the llama.cpp server from [Part 1](/posts/the-loop/), which runs with `-c 32768`. Its message is 326,982 characters long:

```text
$ curl -s http://127.0.0.1:9931/v1/chat/completions -H 'content-type: application/json' -d @over-32k.json
{"error":{"code":400,"message":"request (90926 tokens) exceeds the available context size (32768 tokens),
 try increasing it","type":"exceed_context_size_error","n_prompt_tokens":90926,"n_ctx":32768}}
```

llama.cpp refuses the request with status 400 and says how far over the limit it was. Anthropic's API also refuses a request that does not fit. The agent from [Part 9](/posts/inbox-vs-execution/) treats a refusal as a `ProviderError`: the turn fails, the next prompt sends the same long history, and that turn fails too, so the session stays stuck.

An error is therefore a poor signal for a history that has grown too long. Ollama never sends one, and where an error does come, the turn has already failed. The agent in this Part checks the size itself, before it sends.

### Summarizing instead of dropping messages

Dropping the oldest messages would make the history fit, but it would also drop the user's original request, the files that matter and the decisions made so far. OpenCode, Claude Code and other coding agents take a different route: the model writes a summary of the conversation, and the work continues from it. This is called _compaction_. OpenCode does it in [session/compaction.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts).

With the event log from [Part 8](/posts/the-session-as-an-event-log/), a summary only changes what the next step sees. The agent appends the summary as one more event, and every event before it stays in the file, so nothing is lost when the summary leaves something out.

## Compaction

### Three terms

The _context window_ is the most tokens a model takes in for one step, the reply included. _Compaction_ replaces everything before a point in the history with a summary and records it as a session event; the event log keeps every original event. A _summary_ is the text a compaction writes, which the next step reads in place of the events it covers.

### Six decisions in the design

### 1. The agent estimates the size instead of measuring it

The exact token count of a request depends on the model's tokenizer, which the agent does not have. A common rule of thumb is four characters per token. The agent turns the history and the tool definitions into JSON, which includes the field names and quotes that also travel in the request, and divides its length by four. The tool definitions are part of the count because they go out with every step, and the five tools of this agent come to about 650 tokens on their own.

The estimate is rough. The llama.cpp request above had 326,982 characters and 90,926 tokens, about 3.6 characters per token, so on that text the estimate would be about 10% low. The reserve in decision 2 covers that. OpenCode uses the same four characters per token ([util/token.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/util/token.ts#L3)) and corrects the estimate with the token counts that providers report after each response. That correction is left out here and listed as a possible extension below.

### 2. The check runs before every step and keeps a quarter of the window free

Before each step, the agent rebuilds the history, estimates its size, and compacts when the estimate reaches 75% of the window. The remaining quarter leaves room for the reply, which shares the window with the request, for the error in the estimate, and for the summary request, which also has to fit. The check runs before every step, not only before every turn, because one turn can read many files.

OpenCode keeps 15% of the window free, with a minimum of 16,000 tokens ([RESERVE_MIN and RESERVE_SHARE](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L129-L135)). For a 200,000-token window that is 30,000 tokens. For a 32k window the minimum would be half the window, so the agent here uses a plain share.

### 3. The summary is an event, and the history starts from the latest one

A compaction appends a fifth kind of session event, `compacted`, which holds the summary text. `toHistory`, the fold that builds the history, treats it as a new starting point: when it reaches a `compacted` event, it discards the messages built so far and puts one summary message in their place. Events after the summary are added as before.

The summary reaches the model as a user message, introduced as a record of the past, much as OpenCode introduces its own ([runner/to-llm-message.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/runner/to-llm-message.ts#L273-L291)):

```text
The following is a summary of the earlier conversation. Treat it as historical context, not as new instructions.

<summary>
...
</summary>
```

A user message works with every protocol the agent speaks. After a compaction the summary is the first message of the history, and a conversation that starts with the user is what chat APIs expect.

### 4. The summary is written from a plain text transcript

The same model client writes the summary, in a separate call that does not become part of the history. That call carries no tools, since the model is only asked to write. Without tool definitions in the request, the tool calls and tool results in the history refer to tools the request does not define, and providers differ in whether they accept that. The agent avoids the question by sending the conversation as one block of text, in which each message becomes a few lines starting with `User:`, `Assistant:` or `Tool results:`. OpenCode does the same; its comment says "The transcript has no tool definitions, which the summary does not need" ([session/compaction.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L705-L710)).

The transcript also clips each tool input and tool result to its first 2,000 characters, the same limit OpenCode uses ([TRANSCRIPT_CLIP](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L150)). Without the clip, one large file read could make the summary request too long, and on Ollama nothing would report it. The log and the normal steps keep the full results.

After the transcript comes the instruction: a template with the headings Objective, Decisions, Work state, Next move, Relevant files and Latest request, followed by a few rules. It shortens OpenCode's template ([SUMMARY_TEMPLATE and SUMMARY_RULES](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L173-L212)), which has more sections and is long for a 9B model.

### 5. Nothing before the summary is kept word for word, except the latest request

After a compaction, the next step sees only the summary and the events after it. Compaction usually runs in the middle of a turn, so the summary has to say what the turn is for. The template's last heading, Latest request, asks for the user's newest unanswered request, quoted word for word, so the model that continues from the summary still has the user's own words.

OpenCode keeps more: by default, the newest 15,000 tokens of conversation stay unchanged next to the summary ([Settings.keep](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L46-L47)). That needs a window large enough to spare the room, and it is listed as a possible extension below.

### 6. Failed summaries and restarts

If the summary call fails, or the model returns an empty summary, compaction fails with a `ProviderError`. The turn then fails like any turn with a provider error since [Part 8](/posts/the-session-as-an-event-log/), and the agent appends no `compacted` event, so the next attempt starts from the old history.

Three more rules cover how a summary meets failed turns and restarts:

- Since [Part 8](/posts/the-session-as-an-event-log/), `turn-failed` cuts the history back to the prompt of the failed turn. If the turn compacted partway through, that prompt is now inside the summary, so the fold cuts back to the summary instead. The summary stays, because the tool calls it describes really ran.
- After that cut, the history ends with the summary, which is a user message, and `unansweredCalls` from [Part 8](/posts/the-session-as-an-event-log/) reads such a history as a turn the model still has to answer. `resume` therefore checks the last event first: a turn whose last event is `turn-failed` is over and is not resumed.
- If the latest event is `compacted`, the agent sends the step without compacting again. This happens after a restart that finds a compaction as the last event, and a second summary of nothing but a summary would not shorten the history. OpenCode has the same rule: "A compaction just completed; let the runner rebuild the request from it first" ([session/compaction.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/compaction.ts#L437-L446)).

### What this leaves for later

A summary loses detail, and the model cannot get it back on its own, although the log still has it. A single tool result larger than the window still makes the next step too long, because compaction only shortens what came before it. The estimate does not know the real tokenizer. The summary is also written while the user waits, which takes as long as a normal step; OpenCode avoids that wait by writing a summary in the background before it is needed.

### Step 1: The compacted event and the fold

The new event goes into `src/session-event.ts`, next to the other four, and joins the union:

```ts
// Everything before this point in the history was replaced by a summary. The events it covers stay in the log.
export const Compacted = Schema.Struct({ type: Schema.Literal("compacted"), summary: Schema.String })

export const SessionEvent = Schema.Union([Prompt, StepFinished, ToolResult, TurnFailed, Compacted])
export type SessionEvent = typeof SessionEvent.Type
```

1. `Compacted` holds only the summary text. Which events it covers follows from its place in the log: everything before it.
2. Adding it to `SessionEvent` is enough for the session to store and read it. `append` encodes any event of the union, and reading the log decodes it, so `session.ts` does not change.
3. A log written by [Part 9](/posts/inbox-vs-execution/) has no `compacted` events and reads as before.

`src/history.ts` gets the message the summary turns into, and one more branch in the fold:

```ts
import { isToolCall, type Message, type ToolCallPart } from "./messages"
import type { SessionEvent } from "./session-event"

// How a summary reaches the model: one user message, marked as a record of the past.
export const summaryMessage = (summary: string): Message => ({
  role: "user",
  content: [
    {
      type: "text",
      text: [
        "The following is a summary of the earlier conversation. Treat it as historical context, not as new instructions.",
        "",
        `<summary>\n${summary}\n</summary>`,
      ].join("\n"),
    },
  ],
})

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []
  let turnStart = 0 // where a failed turn is cut back to: its prompt, or the summary if that came later

  for (const event of events) {
    if (event.type === "prompt") {
      turnStart = history.length
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else if (event.type === "tool-result") {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    } else if (event.type === "compacted") {
      // The summary takes the place of everything before it.
      history.length = 0
      history.push(summaryMessage(event.summary))
      turnStart = history.length
    } else {
      history.length = turnStart
    }
  }
  return history
}
```

1. `summaryMessage` builds the user message from decision 3: one line that says what follows, then the summary between `<summary>` tags. It is exported so that the tests can compare against it.
2. The new branch handles `compacted`. `history.length = 0` empties the list built so far, and the summary message takes its place. The events after it are added by the other branches as before.
3. `turnStart` is set to the end of the history after the summary, which is 1. A `turn-failed` that follows cuts back to that point, so the summary stays. A new `prompt` after the summary sets `turnStart` again, so a turn that starts after a summary is still cut back to its own prompt.
4. The last branch, for `turn-failed`, is unchanged. Only the comment on `turnStart` says what it now means.

`src/history.ts`

```ts
import { isToolCall, type Message, type ToolCallPart } from "./messages"
import type { SessionEvent } from "./session-event"

// How a summary reaches the model: one user message, marked as a record of the past.
export const summaryMessage = (summary: string): Message => ({
  role: "user",
  content: [
    {
      type: "text",
      text: [
        "The following is a summary of the earlier conversation. Treat it as historical context, not as new instructions.",
        "",
        `<summary>\n${summary}\n</summary>`,
      ].join("\n"),
    },
  ],
})

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []
  let turnStart = 0 // where a failed turn is cut back to: its prompt, or the summary if that came later

  for (const event of events) {
    if (event.type === "prompt") {
      turnStart = history.length
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else if (event.type === "tool-result") {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    } else if (event.type === "compacted") {
      // The summary takes the place of everything before it.
      history.length = 0
      history.push(summaryMessage(event.summary))
      turnStart = history.length
    } else {
      history.length = turnStart
    }
  }
  return history
}

// What a restart finds when the last turn did not finish: the tool calls of the last step that have no result yet.
// Returns undefined when the turn did finish, and an empty list when the model simply has to answer next.
export const unansweredCalls = (history: ReadonlyArray<Message>): ToolCallPart[] | undefined => {
  const last = history.at(-1)
  if (!last) return undefined
  if (last.role === "user") return []
  const assistant = last.role === "tool" ? history.at(-2) : last
  const calls = assistant?.content.filter(isToolCall) ?? []
  if (last.role === "assistant" && calls.length === 0) return undefined
  const answered = last.role === "tool" ? last.content.flatMap((part) => (part.type === "tool-result" ? [part.id] : [])) : []
  return calls.filter((call) => !answered.includes(call.id))
}
```

`test/history.test.ts`

```ts
import { describe, expect, test } from "bun:test"

import type { ToolResultPart } from "../src/messages"
import type { SessionEvent } from "../src/session-event"

  type: "step-finished",
  message: { role: "assistant", content: [{ type: "text", text }] },
  finish: "stop",
})
const calls = (...ids: string[]): SessionEvent => ({
  type: "step-finished",
  message: { role: "assistant", content: ids.map((id) => ({ type: "tool-call", id, name: "echo", input: {} })) },
  finish: "tool-calls",
})
const result = (id: string): SessionEvent => {
  const part: ToolResultPart = { type: "tool-result", id, name: "echo", result: { type: "text", value: id } }
  return { type: "tool-result", part }
}
const failed: SessionEvent = { type: "turn-failed", reason: "connection reset" }
const compacted = (summary: string): SessionEvent => ({ type: "compacted", summary })

describe("toHistory", () => {
  test("turns events into messages in order", () => {
    const history = toHistory([prompt("hi"), answer("hello")])

    expect(history.map((message) => message.role)).toEqual(["user", "assistant"])
  })

  test("puts results that follow one another in one tool message", () => {
    const history = toHistory([prompt("go"), calls("a", "b"), result("a"), result("b")])

    expect(history.map((message) => message.role)).toEqual(["user", "assistant", "tool"])
```

### Step 2: The context window

The window belongs to a model on a particular server, so it goes on the route, next to the model name. `src/provider.ts` gives each route a `contextWindow` and reads an override from the environment:

1. `Route` has a new field, `contextWindow`, in tokens.
2. Both local routes use 32,768, the context the servers were started with in [Part 1](/posts/the-loop/). A server started with a different context needs a matching value in the route or in `CONTEXT_WINDOW`. The Claude route uses 200,000.
3. `selectRoute` reads `CONTEXT_WINDOW` the way it reads `BASE_URL` and `MODEL`. A value that is not a positive whole number, such as `32k`, fails with a `ConfigError` before the first prompt, like an unknown provider.
4. The override has a second use: a small window, such as 2,000 tokens, makes compaction happen after a few prompts, which is how Step 6 shows it.

The agent never sees the route, only the `ModelClient` service, so the service passes the window on. In `src/model-client.ts` the service gets one more member, and the live layer fills it in:

```ts
  Stream.unwrap(
    Effect.gen(function* () {
      const unreachable = (error: unknown) => new ProviderError({ reason: `Could not reach ${route.baseUrl}: ${messageOf(error)}` })

      const response = yield* Effect.tryPromise({
        try: () =>
          fetch(`${route.baseUrl}${route.protocol.path}`, {
            method: "POST",
            headers: { "content-type": "application/json", ...route.headers },
            body: JSON.stringify(route.protocol.body(route.model, history, tools)),
          }),
        catch: unreachable,
      })
      const body = response.body
      if (!response.ok || !body) {
        const text = yield* Effect.tryPromise({ try: () => response.text(), catch: unreachable })
        return yield* new ProviderError({ reason: `${route.baseUrl} answered ${response.status}: ${text}` })
      }

      // From here on, the answer is still being written. A failure now happens in the middle of a reply.
      const bytes = Stream.fromReadableStream({
        evaluate: () => body,
        onError: (error) => new ProviderError({ reason: `The stream from ${route.baseUrl} broke off: ${messageOf(error)}` }),
      })
      return route.protocol.events(frames(bytes)).pipe(requireFinish(route))
```

```ts
// A text reply, streamed one word at a time.
export const reply = (text: string): Step => [
  ...text.split(/(?<= )/).map((word): ModelEvent => ({ type: "text-delta", text: word })),

  { type: "tool-call", id, name, input },
  { type: "finish", reason: "tool-calls" },

// A step that fails before sending anything.
export const fail = (reason: string): Step => [new ProviderError({ reason })]

// A model that follows a script and records the history it was given at each step.
// `beforeStep` runs when a step starts and holds the stream back until its promise settles.
// `contextWindow` is large unless a test sets it, so compaction only happens in the tests that ask for it.

          const events = Stream.fromIterable(next).pipe(

          )
          return beforeStep ? Stream.unwrap(Effect.promise(() => beforeStep(request)).pipe(Effect.as(events))) : events
        }),
      contextWindow,
    }),
  )

}

// A terminal where the user types the given answers, in order. An answer can be a promise, for a line the user types later.
// When the answers run out, input ends.
// Questions that start with "Allow" are answered from `confirmations` instead, so a confirmation reaches the
// tool that asked even though the reader has already taken every prompt, as the live terminal does.
// `output` holds the finished lines; `writes` holds every piece passed to `write`, in order.
export const scriptedTerminal = (answers: Array<string | Promise<string>>, confirmations: string[] = []) => {
  const output: string[] = []
  const writes: string[] = []
  const queue = [...answers]
  const confirm = [...confirmations]
  let pending = "" // text written since the last line ended
  const layer = Layer.succeed(
    Terminal,
    Terminal.of({
      ask: (prompt) =>
        Effect.suspend(() => {
          output.push(pending + prompt)
          pending = ""
          const next = (prompt.startsWith("Allow") ? confirm : queue).shift()
          if (next === undefined) return Effect.fail(new InputClosed())
          return typeof next === "string" ? Effect.succeed(next) : Effect.promise(() => next)
        }),
      say: (line) =>
        Effect.sync(() => {
          output.push(pending + line)
          pending = ""
        }),
      write: (text) =>
        Effect.sync(() => {
          writes.push(text)
          pending += text
        }),
    }),
  )
  return { layer, output, writes }
}
```

### Step 3: The estimate and the summary

Everything about compaction itself goes into a new file, `src/compaction.ts`. It starts with the estimate and the threshold:

```ts
import { Effect, Stream } from "effect"
import { ProviderError, type SessionCorrupt } from "./errors"
import { toHistory } from "./history"
import type { Message, Part } from "./messages"
import { ModelClient } from "./model-client"
import { Session } from "./session"
import { Terminal } from "./terminal"
import type { Tool } from "./tool"

// A rough count of what one step sends: the history and the tool definitions, at about four characters per token.
// JSON.stringify leaves out each tool's `run` function, which never goes to the model.
export const estimateTokens = (history: ReadonlyArray<Message>, tools: ReadonlyArray<Tool>) =>
  Math.ceil(JSON.stringify([history, tools]).length / 4)

// The share of the window kept free for the model's reply, and for the summary when it is written.
const RESERVE = 0.25

export const isDue = (estimate: number, contextWindow: number) => estimate >= contextWindow * (1 - RESERVE)
```

1. `estimateTokens` turns the history and the tools into one JSON string and divides its length by four, rounded up. Each tool's `run` is a function, and `JSON.stringify` leaves functions out, so what is counted is the name, the description and the input schema: what the model receives.
2. `RESERVE` is the share of the window kept free, 25% from decision 2.
3. `isDue` says whether an estimate has reached the threshold. It is a separate function so the tests can check the boundary.

Next comes the transcript that the summary is written from:

```ts
// Tool results and tool inputs, such as the content of a file to write, can be long. In the summary request
// each one keeps its first characters only.
const CLIP = 2_000

const clip = (text: string) => (text.length <= CLIP ? text : `${text.slice(0, CLIP)}\n[... ${text.length - CLIP} more characters]`)

const partToText = (part: Part) => {
  if (part.type === "text") return part.text
  if (part.type === "tool-call") return `[called ${part.name}(${clip(JSON.stringify(part.input))})]`
  return `[${part.name} ${part.result.type === "error" ? "failed" : "returned"}]\n${clip(part.result.value)}`
}

// The history as plain text. The summary request carries no tools, and some providers refuse tool calls and
// results in a request that defines no tools, so the conversation goes out as one text instead.
export const transcript = (history: ReadonlyArray<Message>) =>
  history
    .map((message) => {
      const who = message.role === "assistant" ? "Assistant" : message.role === "tool" ? "Tool results" : "User"
      return `${who}:\n${message.content.map(partToText).join("\n")}`
    })
    .join("\n\n")
```

1. `clip` keeps the first 2,000 characters of a text and says how many it left out, so the model knows the text went on.
2. `partToText` writes one content part as text. Text stays as it is. A tool call becomes a line with the tool's name and its clipped input. A tool result becomes a line that says whether the tool returned or failed, followed by the clipped output.
3. `transcript` writes each message as a label and its parts, and separates messages with a blank line. A summary from an earlier compaction is a user message, so it appears as the first `User:` entry, and the new summary takes it into account.

```ts
- Do not continue the task and do not call tools. Return only the summary.`
```

1. The first paragraph tells the model who will read the summary: an agent with no other record of the conversation.
2. The headings ask for the goal, the decisions, the state of the work and the next actions, which is what an agent needs to continue. Relevant files gives paths, so the next agent can read a file again instead of relying on the summary.
3. Latest request is decision 5: the user's newest unanswered request, word for word.
4. The rules keep the summary short and keep exact strings exact, so a summary names the file and quotes the error instead of saying "fixed the error in the config".

The file ends with the summary request and the Effect that runs a compaction:

```ts

  {
    role: "user",
    content: [{ type: "text", text: `<conversation>\n${transcript(history)}\n</conversation>\n\n${SUMMARY_PROMPT}` }],
  },

// of the history so far, and the summary is appended to the log. The next step then starts from it.
export const compactIfDue = (tools: Tool[]): Effect.Effect<void, ProviderError | SessionCorrupt, ModelClient | Session | Terminal> =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const session = yield* Session
    const terminal = yield* Terminal

    const events = yield* session.events
    // Right after a compaction the history cannot get any shorter, so the step goes out as it is.
    if (events.at(-1)?.type === "compacted") return
    const history = toHistory(events)
    const before = estimateTokens(history, tools)
    if (!isDue(before, model.contextWindow)) return

    yield* terminal.say(`[compacting: ~${before} tokens]`)
    const summary = yield* model.chat(summaryRequest(history), []).pipe(
      Stream.runFold(
        () => "",
        (text, event) => (event.type === "text-delta" ? text + event.text : text),
      ),
      Effect.map((text) => text.trim()),
    )
    if (!summary) return yield* new ProviderError({ reason: "The model returned an empty summary" })

    yield* session.append({ type: "compacted", summary })
    const after = estimateTokens(toHistory([...events, { type: "compacted", summary }]), tools)
    yield* terminal.say(`[compacted: ${before} → ${after} tokens]`)
  })
```

1. `summaryRequest` builds a history of one user message: the transcript between `<conversation>` tags, then the instruction.
2. `compactIfDue` reads the log once. If the latest event is already `compacted`, it returns, which is the third rule of decision 6.
3. It rebuilds the history from those events with `toHistory` and estimates it together with the tools. On almost every step the estimate is below the threshold, and `compactIfDue` returns here.
4. Otherwise it prints `[compacting: ~N tokens]` and calls the model with the summary request and no tools. `Stream.runFold` collects the text of the reply and ignores every other event, so a tool call the model attempts anyway is dropped. Nothing is printed while the summary streams.
5. An empty summary fails with a `ProviderError`, as a failed model call already does, and nothing is appended.
6. A summary that came back is appended as a `compacted` event. The new size is estimated from the same events plus the new one, without reading the log again, and printed as `[compacted: N → M tokens]`.
7. Its error type is `ProviderError | SessionCorrupt`, the same as `step`, so the code that calls it needs no new error handling.

### Step 4: Compact before every step

In `src/agent.ts`, `run` calls `compactIfDue` at the top of its loop, before each step. `compactIfDue` is imported from `./compaction`:

```ts
// Steps until the model stops asking for tools. Each result is appended as soon as its tool finishes.
// Before each step, the history is compacted if the request would come close to the context window.
const run = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    yield* compactIfDue(tools)
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }
  }
})
```

1. `yield* compactIfDue(tools)` runs before every `step`, including the first step of a turn, right after the prompt was delivered. A compaction at that point covers the new prompt too, which is why the template asks for the latest request word for word.

3. A failed compaction fails `run` with a `ProviderError`, and `guarded` in the REPL records `turn-failed`, as it does for a failed step.

### Step 5: Restarts after a compaction

A process can die at any moment, including just after a compaction, and the restart from [Part 8](/posts/the-session-as-an-event-log/) has to read such a log correctly. `resume` needs one change, the second rule of decision 6.
```ts
// A restart can find a turn that did not finish. Tool calls without a result get an error result instead of
// running again, since a command that already ran must not run twice. Then the turn continues.
const resume = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const events = yield* session.events
  // A failed turn is over. After a compaction its history can end in the summary, which reads like an open turn.
  if (events.at(-1)?.type === "turn-failed") return
  const calls = unansweredCalls(toHistory(events))
  if (calls === undefined) return

  yield* terminal.say(`[resuming session ${session.id}]`)
  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})
```

1. `session.events` reads the log once. The check and the history both come from that one read.

```ts
import { compactIfDue } from "./compaction"
import { messageOf, type InputClosed, type ProviderError, type SessionCorrupt } from "./errors"
import type { FinishReason } from "./events"
import { toHistory, unansweredCalls } from "./history"
import { isToolCall, type Message, type Part } from "./messages"
import { ModelClient } from "./model-client"
import { Session } from "./session"
import { Terminal } from "./terminal"
import { runTool, Tools, type Tool } from "./tool"

// One step: reload the history from the log, stream the model's events, show the text as it arrives,
// and append the finished message to the log.
const step = (tools: Tool[]) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const session = yield* Session
    const history = yield* session.history
    const content: Part[] = []
    let text = "" // the text block being written, if any
    const outcome: { finish: FinishReason; native?: unknown } = { finish: "stop" }

    // A text block ends when anything else arrives, or when the stream does, even by failing.
    const endText = Effect.suspend(() => {
      if (!text) return Effect.void
      content.push({ type: "text", text })
      text = ""
      return terminal.say("")
    })

    yield* Stream.runForEach(model.chat(history, tools), (event) =>
      Effect.gen(function* () {
        if (event.type === "text-delta") {
          if (!text) yield* terminal.write("Agent: ")
          text += event.text
          yield* terminal.write(event.text)
          return
        }
        yield* endText
        if (event.type === "tool-call") content.push(event)
        else {
          outcome.finish = event.reason
          outcome.native = event.native
        }
      }),
    ).pipe(Effect.ensuring(endText))

    const message: Message = { role: "assistant", content, ...(outcome.native === undefined ? {} : { native: outcome.native }) }
    yield* session.append({ type: "step-finished", message, finish: outcome.finish })
    return { message, finish: outcome.finish }
  })

// Steps until the model stops asking for tools. Each result is appended as soon as its tool finishes.
// Before each step, the history is compacted if the request would come close to the context window.
const run = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    yield* compactIfDue(tools)
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }
  }
})

const interrupted =
  "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it."

// A restart can find a turn that did not finish. Tool calls without a result get an error result instead of
// running again, since a command that already ran must not run twice. Then the turn continues.
const resume = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const events = yield* session.events
  // A failed turn is over. After a compaction its history can end in the summary, which reads like an open turn.
  if (events.at(-1)?.type === "turn-failed") return
  const calls = unansweredCalls(toHistory(events))
  if (calls === undefined) return

  yield* terminal.say(`[resuming session ${session.id}]`)
  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})

const queued = (count: number) => `${count} queued prompt${count === 1 ? "" : "s"}`

// The read-eval-print loop, in two halves that do not wait for each other.
// - The reader asks for a line, saves it in the inbox, and asks again, even while a turn is running.
// - The worker finishes an interrupted turn, then delivers one prompt at a time and runs its turn.
// The reader rings a bell after each prompt. The ring carries no prompt: it only tells the worker to look at the inbox.
export const repl = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session

  // A turn that fails is recorded as failed, so the next prompt starts from a consistent history.
  const failed = (label: string, reason: string) =>
    session.append({ type: "turn-failed", reason }).pipe(Effect.andThen(terminal.say(`[${label}] ${reason}`)))
  const guarded = <R>(work: Effect.Effect<void, ProviderError | SessionCorrupt | InputClosed, R>) =>
    work.pipe(
      Effect.catchTag("ProviderError", (error) => failed("provider error", error.message)),
      Effect.catchDefect((defect) => failed("bug", messageOf(defect))),
    )

  // At most one ring waits at a time: two rings in a row mean the same thing as one.
  const wake = yield* Queue.dropping<void>(1)
  let inputEnded = false

  const reader = Effect.gen(function* () {
    while (true) {
      const input = yield* terminal.ask("You: ")
      yield* session.admit(input)
      yield* terminal.say("[queued]")
      yield* Queue.offer(wake, undefined)
    }
  }).pipe(
    Effect.catchTag("InputClosed", () => Effect.sync(() => void (inputEnded = true))),
    Effect.andThen(Queue.offer(wake, undefined)),
  )

  // What the last run left in the inbox, counted before the reader can add anything.
  const left = yield* session.pending
  if (left > 0) yield* terminal.say(`[${queued(left)} from an earlier run]`)

  yield* Effect.forkChild(reader)
  yield* guarded(resume)

  while (true) {
    // Read before delivering: a prompt admitted before the input ended is then always found by the delivery below.
    const ended = inputEnded
    if ((yield* session.deliver) !== undefined) {
      yield* guarded(run)
      continue
    }
    if (ended) return
    yield* Queue.take(wake)
  }
})
```

### Step 6: A small window and a real model

With the real 32k window, a session needs many prompts before it compacts. `CONTEXT_WINDOW=2000` lowers the threshold to 1,500 tokens, about 650 of which are the tool definitions, so compaction comes after a few prompts. The first run pipes in three prompts: a story, two file reads, and a second story. The database goes into a separate file, so the run starts with an empty session:

The stories are shortened here to their first lines. The history grew with each turn, but each check before a step found it under 1,500 tokens, so nothing was compacted. The check before the first step of this turn found the history at about 1,700 tokens, over the threshold.
```text
$ printf '%s\n' "Read README.md, then notes/todo.txt, then secret-file.txt, one file at a time, and then tell me in one sentence what each file contains." | CONTEXT_WINDOW=1100 DB_PATH=../mid-turn.db bun ../src/index.ts
You: [queued]

[tool] read_file({"path":"notes/todo.txt"})
[compacting: ~854 tokens]
[compacted: 854 → 959 tokens]
[tool] read_file({"path":"secret-file.txt"})
[compacting: ~1050 tokens]
[compacted: 1050 → 974 tokens]
Agent: - **README.md**: This is the project documentation for "Playground."
- **notes/todo.txt**: This file lists personal to-do items ("buy milk", "water the plants").
- **secret-file.txt**: This file contains a riddle about a key ("I have keys but no locks...").
```

> **Watch for this.** Here the summary was longer than the history it replaced: 854 tokens became 959. The files are tiny, and a summary that follows a six-heading template has a minimum size. With a window this close to the fixed cost of the tool definitions, every step is over the threshold, so the agent compacts before every step. The turn still finishes correctly, but each step costs two model calls. Compaction shortens the history only when the history is much longer than a summary, as it is with a real window, so a window set by hand works best with several thousand tokens above the tool definitions.

> **Result.** Before every step, the agent estimates the size of the next request. At three quarters of the context window, the model writes a summary from a clipped transcript, the agent appends it to the log, and the next step starts from it. The log keeps every event, a failed summary fails the turn like any provider error, and a restart reads a log that contains summaries correctly.

### Possible extensions

These additions fit the design and are not built here:

- The agent could use measured sizes. Providers report how many tokens a request used: OpenAI-style servers in a `usage` field when the request sets `stream_options: {"include_usage": true}`, and Anthropic in the `message_start` and `message_delta` events. The `finish` model event could carry that number and `step-finished` could store it, so the estimate would only need to cover what was added since the last step.
- The agent could compact after a refusal. llama.cpp's `exceed_context_size_error` says exactly what went wrong, so the agent could recognize it, compact, and send the step once more, as a fallback behind the estimate.
- Compaction could keep the newest few thousand tokens of the history as they are and summarize only the rest, splitting at a step boundary so that a tool call never loses its result. The `compacted` event would then also record where the kept part starts.
- The agent could skip a compaction that does not help, by comparing the history without the tool definitions to a minimum size, such as 2,000 tokens, and sending the step unchanged below it. That avoids the case in the callout above.

### OpenCode does more

OpenCode's compaction goes further than this Part:

- It uses native compaction where a provider offers it, so the provider compacts the conversation itself.
- It can write a summary in the background before one is due, and swap it in when compaction runs.
- When even the transcript is too long, it shortens the oldest exchanges first.
- When a summary ignores the required headings, it asks once more.
- On a later compaction, it asks the model to update the previous summary instead of writing a new one.

```ts
import { isToolCall, type Message, type ToolCallPart } from "./messages"
import type { SessionEvent } from "./session-event"

// How a summary reaches the model: one user message, marked as a record of the past.
export const summaryMessage = (summary: string): Message => ({
  role: "user",
  content: [
    {
      type: "text",
      text: [
        "The following is a summary of the earlier conversation. Treat it as historical context, not as new instructions.",
        "",
        `<summary>\n${summary}\n</summary>`,
      ].join("\n"),
    },
  ],
})

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []
  let turnStart = 0 // where a failed turn is cut back to: its prompt, or the summary if that came later

  for (const event of events) {
    if (event.type === "prompt") {
      turnStart = history.length
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else if (event.type === "tool-result") {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    } else if (event.type === "compacted") {
      // The summary takes the place of everything before it.
      history.length = 0
      history.push(summaryMessage(event.summary))
      turnStart = history.length
    } else {
      history.length = turnStart
    }
  }
  return history
}

// What a restart finds when the last turn did not finish: the tool calls of the last step that have no result yet.
// Returns undefined when the turn did finish, and an empty list when the model simply has to answer next.
export const unansweredCalls = (history: ReadonlyArray<Message>): ToolCallPart[] | undefined => {
  const last = history.at(-1)
  if (!last) return undefined
  if (last.role === "user") return []
  const assistant = last.role === "tool" ? history.at(-2) : last
  const calls = assistant?.content.filter(isToolCall) ?? []
  if (last.role === "assistant" && calls.length === 0) return undefined
  const answered = last.role === "tool" ? last.content.flatMap((part) => (part.type === "tool-result" ? [part.id] : [])) : []
  return calls.filter((call) => !answered.includes(call.id))
}
```

```ts
export const selectRoute = (env: Env): Effect.Effect<Route, ConfigError> => {

    let finished = false
    return events.pipe(
      Stream.tap((event) =>
        Effect.sync(() => {
          if (event.type === "finish") finished = true
        }),
      ),
      Stream.onEnd(
        Effect.suspend(() =>
          finished ? Effect.void : Effect.fail(new ProviderError({ reason: `The stream from ${route.baseUrl} ended before the model finished` })),
        ),
      ),
    )
  })

// One step: one model call, as a stream of events. It fails with a ProviderError that the user reads; the model never sees it.
export const chat = (route: Route, history: Message[], tools: Tool[]): Stream.Stream<ModelEvent, ProviderError> =>
  Stream.unwrap(
    Effect.gen(function* () {
      const unreachable = (error: unknown) => new ProviderError({ reason: `Could not reach ${route.baseUrl}: ${messageOf(error)}` })

      const response = yield* Effect.tryPromise({
        try: () =>
          fetch(`${route.baseUrl}${route.protocol.path}`, {
            method: "POST",
            headers: { "content-type": "application/json", ...route.headers },
            body: JSON.stringify(route.protocol.body(route.model, history, tools)),
          }),
        catch: unreachable,
      })
      const body = response.body
      if (!response.ok || !body) {
        const text = yield* Effect.tryPromise({ try: () => response.text(), catch: unreachable })
        return yield* new ProviderError({ reason: `${route.baseUrl} answered ${response.status}: ${text}` })
      }

      // From here on, the answer is still being written. A failure now happens in the middle of a reply.
      const bytes = Stream.fromReadableStream({
        evaluate: () => body,
        onError: (error) => new ProviderError({ reason: `The stream from ${route.baseUrl} broke off: ${messageOf(error)}` }),
      })
      return route.protocol.events(frames(bytes)).pipe(requireFinish(route))
    }),
  )
```

```ts
  if (part.type === "tool-call") return `[called ${part.name}(${clip(JSON.stringify(part.input))})]`

## Decisions
- [decisions already made, and why]

## Work state
- [what is done, what is in progress, what is blocked]

## Next move
1. [the next actions, in order]

- [path]: [why it matters]

[the user's latest request that is not yet fully answered, quoted word for word]

- Use short, single-line bullets.
- Keep exact file paths, commands, error messages and identifiers.

    const terminal = yield* Terminal

    const events = yield* session.events
    // Right after a compaction the history cannot get any shorter, so the step goes out as it is.
    if (events.at(-1)?.type === "compacted") return
    const history = toHistory(events)
    const before = estimateTokens(history, tools)
    if (!isDue(before, model.contextWindow)) return

    yield* terminal.say(`[compacting: ~${before} tokens]`)

    if (!summary) return yield* new ProviderError({ reason: "The model returned an empty summary" })

    yield* session.append({ type: "compacted", summary })
```

```ts
// and append the finished message to the log.
const step = (tools: Tool[]) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const session = yield* Session
    const history = yield* session.history
    const content: Part[] = []
    let text = "" // the text block being written, if any
    const outcome: { finish: FinishReason; native?: unknown } = { finish: "stop" }

    // A text block ends when anything else arrives, or when the stream does, even by failing.
    const endText = Effect.suspend(() => {
      if (!text) return Effect.void
      content.push({ type: "text", text })
      text = ""
      return terminal.say("")
    })

    yield* Stream.runForEach(model.chat(history, tools), (event) =>
      Effect.gen(function* () {
        if (event.type === "text-delta") {
          if (!text) yield* terminal.write("Agent: ")
          text += event.text
          yield* terminal.write(event.text)
          return
        }
        yield* endText
        if (event.type === "tool-call") content.push(event)
        else {
          outcome.finish = event.reason
          outcome.native = event.native
        }
      }),
    ).pipe(Effect.ensuring(endText))

    const message: Message = { role: "assistant", content, ...(outcome.native === undefined ? {} : { native: outcome.native }) }
    yield* session.append({ type: "step-finished", message, finish: outcome.finish })
    return { message, finish: outcome.finish }
  })

// Before each step, the history is compacted if the request would come close to the context window.

  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    yield* compactIfDue(tools)
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }

  "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it."

// running again, since a command that already ran must not run twice. Then the turn continues.

  const session = yield* Session
  const events = yield* session.events
  // A failed turn is over. After a compaction its history can end in the summary, which reads like an open turn.
  if (events.at(-1)?.type === "turn-failed") return
  const calls = unansweredCalls(toHistory(events))
  if (calls === undefined) return

  yield* terminal.say(`[resuming session ${session.id}]`)
  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})

// - The reader asks for a line, saves it in the inbox, and asks again, even while a turn is running.
// - The worker finishes an interrupted turn, then delivers one prompt at a time and runs its turn.
// The reader rings a bell after each prompt. The ring carries no prompt: it only tells the worker to look at the inbox.
export const repl = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session

  // A turn that fails is recorded as failed, so the next prompt starts from a consistent history.
  const failed = (label: string, reason: string) =>
    session.append({ type: "turn-failed", reason }).pipe(Effect.andThen(terminal.say(`[${label}] ${reason}`)))
  const guarded = <R>(work: Effect.Effect<void, ProviderError | SessionCorrupt | InputClosed, R>) =>
    work.pipe(
      Effect.catchTag("ProviderError", (error) => failed("provider error", error.message)),
      Effect.catchDefect((defect) => failed("bug", messageOf(defect))),
    )

  // At most one ring waits at a time: two rings in a row mean the same thing as one.
  const wake = yield* Queue.dropping<void>(1)
  let inputEnded = false

  const reader = Effect.gen(function* () {
    while (true) {
      const input = yield* terminal.ask("You: ")
      yield* session.admit(input)
      yield* terminal.say("[queued]")
      yield* Queue.offer(wake, undefined)
    }
  }).pipe(
    Effect.catchTag("InputClosed", () => Effect.sync(() => void (inputEnded = true))),
    Effect.andThen(Queue.offer(wake, undefined)),
  )

  // What the last run left in the inbox, counted before the reader can add anything.
  const left = yield* session.pending
  if (left > 0) yield* terminal.say(`[${queued(left)} from an earlier run]`)

  yield* Effect.forkChild(reader)
  yield* guarded(resume)

  while (true) {
    // Read before delivering: a prompt admitted before the input ended is then always found by the delivery below.
    const ended = inputEnded
    if ((yield* session.deliver) !== undefined) {
      yield* guarded(run)
      continue
    }
    if (ended) return
    yield* Queue.take(wake)
  }
})
```

```ts
// tool that asked even though the reader has already taken every prompt, as the live terminal does.
// `output` holds the finished lines; `writes` holds every piece passed to `write`, in order.
export const scriptedTerminal = (answers: Array<string | Promise<string>>, confirmations: string[] = []) => {
  const output: string[] = []
  const writes: string[] = []
  const queue = [...answers]
  const confirm = [...confirmations]
  let pending = "" // text written since the last line ended
  const layer = Layer.succeed(
    Terminal,
    Terminal.of({
      ask: (prompt) =>
        Effect.suspend(() => {
          output.push(pending + prompt)
          pending = ""
          const next = (prompt.startsWith("Allow") ? confirm : queue).shift()
          if (next === undefined) return Effect.fail(new InputClosed())
          return typeof next === "string" ? Effect.succeed(next) : Effect.promise(() => next)
        }),
      say: (line) =>
        Effect.sync(() => {
          output.push(pending + line)
          pending = ""
        }),
      write: (text) =>
        Effect.sync(() => {
          writes.push(text)
          pending += text
        }),
    }),
  )
  return { layer, output, writes }
```

```ts
import { afterEach, beforeEach, describe, expect, test } from "bun:test"
import { Effect, Layer, Schema } from "effect"
import { mkdtemp, rm } from "node:fs/promises"
import { tmpdir } from "node:os"
import { join } from "node:path"
import { repl } from "../src/agent"
import type { SessionEvent } from "../src/session-event"
import { Session, SessionLive } from "../src/session"
import { defineTool, Tools } from "../src/tool"
import { summaryMessage } from "../src/history"
import { callTool, reply, scriptedModel, scriptedTerminal } from "./fakes"

// A crash leaves the log as it was at the moment the process died. These tests write that log with
// `append`, close the file, and start the agent again on it.
let dir: string
beforeEach(async () => {
  dir = await mkdtemp(join(tmpdir(), "agent-session-"))
})
afterEach(() => rm(dir, { recursive: true, force: true }))

const ran: string[] = []
const echo = defineTool({
  name: "echo",
  description: "Returns its text.",
  input: Schema.Struct({ text: Schema.String }),
  execute: async ({ text }) => (ran.push(text), text),
})

const prompt = (text: string): SessionEvent => ({ type: "prompt", text })
const calls = (...ids: string[]): SessionEvent => ({
  type: "step-finished",
  message: { role: "assistant", content: ids.map((id) => ({ type: "tool-call", id, name: "echo", input: { text: id } })) },
  finish: "tool-calls",
})
const result = (id: string): SessionEvent => ({
  type: "tool-result",
  part: { type: "tool-result", id, name: "echo", result: { type: "text", value: id } },
})

// Process one: the events that were written before the crash, and the prompts that were still in the inbox.
const crashAfter = (events: SessionEvent[], inbox: string[] = []) =>
  Effect.runPromise(
    Effect.gen(function* () {
      const session = yield* Session
      for (const event of events) yield* session.append(event)
      for (const text of inbox) yield* session.admit(text)
    }).pipe(Effect.provide(SessionLive({ path: join(dir, "agent.db"), id: "s" }))),
  )

// Process two: a new agent on the same file. No input, so it only finishes what it finds.
const restart = async (modelSteps: Parameters<typeof scriptedModel>[0], contextWindow?: number) => {
  const model = scriptedModel(modelSteps, undefined, contextWindow)
  const terminal = scriptedTerminal([])
  const layers = Layer.mergeAll(model.layer, terminal.layer, Layer.succeed(Tools, [echo]), SessionLive({ path: join(dir, "agent.db"), id: "s" }))
  const events = await Effect.runPromise(
    Effect.gen(function* () {
      yield* repl
      return yield* (yield* Session).events
    }).pipe(Effect.provide(layers)),
  )
  return { events, requests: model.requests, output: terminal.output }
}

describe("resuming a session", () => {
  test("answers a call that has no result with an error and never runs it again", async () => {
    ran.length = 0
    await crashAfter([prompt("go"), calls("a", "b"), result("a")])

    const { events, requests, output } = await restart([reply("Understood.")])

    expect(output[0]).toBe("[resuming session s]")
    expect(ran).toEqual([])
    const tool = requests[0]?.at(-1)
    expect(tool?.role).toBe("tool")
    expect(tool?.content.map((part) => (part.type === "tool-result" ? [part.id, part.result.type] : []))).toEqual([
      ["a", "text"],
      ["b", "error"],
    ])
    expect(JSON.stringify(tool)).toContain("stopped before this tool finished")
    expect(events.map((event) => event.type)).toEqual(["prompt", "step-finished", "tool-result", "tool-result", "step-finished"])
  })

  test("continues a turn that stopped right after the prompt", async () => {
    await crashAfter([prompt("hello")])

    const { requests, output } = await restart([reply("Hi.")])

    expect(output).toContain("Agent: Hi.")
    expect(requests[0]?.map((message) => message.role)).toEqual(["user"])
  })

  test("continues a turn that stopped between the last result and the next step", async () => {
    await crashAfter([prompt("go"), calls("a"), result("a")])

    const { requests } = await restart([reply("Done.")])

    expect(requests[0]?.map((message) => message.role)).toEqual(["user", "assistant", "tool"])
  })

  test("leaves a finished turn alone", async () => {
    await crashAfter([prompt("hi"), { type: "step-finished", message: { role: "assistant", content: [{ type: "text", text: "Hello." }] }, finish: "stop" }])

    const { requests, output } = await restart([])

    expect(requests).toEqual([])
    expect(output.join("\n")).not.toContain("resuming")
  })

  test("leaves a failed turn alone", async () => {
    await crashAfter([prompt("hi"), { type: "turn-failed", reason: "connection reset" }])

    const { requests, output } = await restart([])

    expect(requests).toEqual([])
    expect(output.join("\n")).not.toContain("resuming")
  })

  test("a resumed turn that calls a tool runs it like any other", async () => {
    ran.length = 0
    await crashAfter([prompt("go")])

    await restart([callTool("c9", "echo", { text: "again" }), reply("Done.")])

    expect(ran).toEqual(["again"])
  })

  test("runs the prompts that were still in the inbox, in order", async () => {
    await crashAfter([], ["one", "two"])

    const { events, output } = await restart([reply("A."), reply("B.")])

    expect(output).toContain("[2 queued prompts from an earlier run]")
    expect(events.map((event) => (event.type === "prompt" ? event.text : event.type))).toEqual(["one", "step-finished", "two", "step-finished"])
  })

  test("finishes the interrupted turn before it delivers the next prompt", async () => {
    await crashAfter([prompt("first")], ["second"])

    const { events, requests, output } = await restart([reply("A."), reply("B.")])

    expect(output.slice(0, 2)).toEqual(["[1 queued prompt from an earlier run]", "[resuming session s]"])
    expect(requests[0]?.map((message) => message.role)).toEqual(["user"])
    expect(events.map((event) => (event.type === "prompt" ? event.text : event.type))).toEqual(["first", "step-finished", "second", "step-finished"])
  })

  test("says nothing about the inbox when it is empty", async () => {
    await crashAfter([prompt("hi"), { type: "step-finished", message: { role: "assistant", content: [{ type: "text", text: "Hello." }] }, finish: "stop" }])

    const { output } = await restart([])

    expect(output.join("\n")).not.toContain("queued prompt")
  })

  test("continues a turn that stopped right after a compaction, from the summary", async () => {
    await crashAfter([prompt("go"), calls("a"), result("a"), { type: "compacted", summary: "S1" }])

    const { requests, output } = await restart([reply("Done.")])

    expect(output).toContain("[resuming session s]")
    expect(requests[0]).toEqual([summaryMessage("S1")])
  })

  test("does not summarize a history that is already only a summary", async () => {
    await crashAfter([prompt("go"), { type: "compacted", summary: "S1" }])

    // A window of 10 tokens: even the summary is over the limit.
    const { requests, events } = await restart([reply("Done.")], 10)

    expect(requests).toEqual([[summaryMessage("S1")]])
    expect(events.map((event) => event.type)).toEqual(["prompt", "compacted", "step-finished"])
  })

  test("leaves a turn alone that failed after a compaction", async () => {
    await crashAfter([prompt("go"), calls("a"), result("a"), { type: "compacted", summary: "S1" }, { type: "turn-failed", reason: "connection reset" }])

    const { requests, output } = await restart([])

    expect(requests).toEqual([])
    expect(output.join("\n")).not.toContain("resuming")
  })
})
```

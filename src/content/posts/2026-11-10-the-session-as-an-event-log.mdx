## Foreword

This Part moves the conversation of the agent from [Part 7](/posts/streaming/) out of memory and into a SQLite file. Every prompt, finished step and tool result is appended as it happens, the history for each step is rebuilt from the file, and a restart finishes the turn the last run left unfinished. It is the first Part of Stage B (Session) in [the roadmap](/posts/the-roadmap/).

The code for this Part is available as the [`Part8_persistent_session` snapshot of vfil/sigma-agent](https://github.com/vfil/sigma-agent/tree/Part8_persistent_session), the repo where I build this agent in parallel.

## Start from what the process forgets

The agent from [Part 7](/posts/streaming/) keeps the conversation in an array. `index.ts` passes `repl` an empty one, `turn` pushes every message onto it, and when the process ends the array goes with it. Close the terminal after twenty minutes of work and the next run starts with no memory of the files it read, the commands it ran or what the user asked.

The end of [Part 2](/posts/the-roadmap/) asked what is lost when Ctrl-C stops an agent halfway through a task, and what the smallest thing is that must be on disk to get it back. The first half has a precise answer. Everything the process knew is lost: the messages, and also which tool calls had finished. The second half is what this Part builds. The record built here is one entry per fact, written when the fact happens: the prompt, each finished step, each tool result. The rest, such as the order of the messages or which calls still wait for a result, can be worked out from those entries, so nothing else is saved.

What a restart finds depends on where the process died. Each row of this table is one place it can die, with what the file holds and what the next run has to do:

| The process dies...                          | The file ends with                  | The next run has to                                                       |
| -------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------- |
| before the model has answered the prompt     | the prompt                          | call the model                                                            |
| while a reply is streaming                   | the prompt, or the last tool result | call the model again; the half reply was never stored                     |
| after a step asked for tools, before any ran | the step, with its tool calls       | give each call a result that says it was interrupted, then call the model |
| while a tool runs, or between two tools      | the step, and the results so far    | the same, for the calls that have no result                               |
| after the last tool result                   | that result                         | call the model                                                            |
| after the final answer                       | the step with no tool calls         | nothing                                                                   |

The agent changes in three places. Each fact is appended to a SQLite table as it happens. The history for a step is rebuilt from that table instead of read from an array. And at startup, the agent looks at where the last turn ended and finishes it.

## The log

### A short introduction to Drizzle

The table is declared and queried with [Drizzle](https://orm.drizzle.team/), a TypeScript ORM. An ORM (object-relational mapper) is a library that maps database tables to typed code: the table is declared once as a TypeScript value, and the queries built from it are checked by the compiler. Drizzle also comes with a command-line tool, Drizzle Kit, that compares the declared tables with the previous version and writes the difference as a _migration_, a SQL file that takes a database from one version of its schema to the next. The program applies the migrations when it starts, so a database file is created, or brought up to date, by the same code that uses it.

Drizzle's own [getting started guide for Bun and SQLite](https://orm.drizzle.team/docs/get-started/bun-sqlite-new) covers the plain version of what follows: install, declare a table, connect, run queries. Two things differ here. This Part uses the Effect driver, `drizzle-orm/effect-sqlite-bun`, in which every query is an Effect that is run with `yield*` and fails with a typed error, like everything else in the agent. It runs on `@effect/sql-sqlite-bun`, Effect's own SQLite client for Bun. And the driver is part of Drizzle's 1.0 release candidate, which is the line OpenCode builds on ([core/src/database/database.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/database/database.ts#L14), which also applies its migrations at startup, on [line 51](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/database/database.ts#L51)). The code below pins exact versions, because a release candidate can still change.

### Four words

Four terms are used from here on. A _session_ is the durable record of one conversation. A _session event_ is one fact appended to it. The _event log_ is the ordered events of one session, and the _history_ is the list of messages the next step sends to the model, rebuilt from the log. A session event is a different thing from a model event: model events are what a step's stream carries while the model answers, and they are never stored.

### Six decisions in the design

### 1. Four events, and each one a fact that cannot be worked out from the others

OpenCode's AGENTS.md says to record only the irreducible: "Keep durable events minimal: record irreducible new facts and do not repeat state derivable by folding the ordered aggregate history". Applied to this agent, that leaves four events:

| Event           | The fact                                                                 | When it is appended                                 |
| --------------- | ------------------------------------------------------------------------ | --------------------------------------------------- |
| `prompt`        | The user said this                                                       | When the user's line is read                        |
| `step-finished` | The model answered with this message, and the step ended for this reason | When the stream of a step has ended                 |
| `tool-result`   | This tool call produced this result                                      | As soon as each tool finishes, one event per call   |
| `turn-failed`   | The turn ended in an error                                               | When a provider error or a bug ends a turn (step 4) |

Text pieces are not events. The finished message already holds the whole text, and nothing needs the pieces after the screen showed them. There is no `step-started` or `tool-called` either, because the call is inside the `step-finished` that asked for it. A tool result is one event per call and not one per step. A step that asks for three tools and dies after the first has one result worth keeping.

### 2. The history is a fold of the events

The history is not stored anywhere. A function, `toHistory`, reads the events in order and builds the messages: a `prompt` becomes a user message, a `step-finished` becomes its assistant message, and the `tool-result` events that follow one another become one `tool` message, which is the shape [Part 4](/posts/providers-behind-one-interface/) chose. (A _fold_ is a loop that walks a list and builds one value from it, the way `reduce` does.) Because the function only reads, it can be tested without a database, and the same events always give the same history.

### 3. The history is rebuilt before every step

OpenCode's AGENTS.md has a rule that [Part 2](/posts/the-roadmap/) quoted: "Each step is one explicit `llm.stream` call that continues from reloaded history. Do not add an in-memory tool loop." The loop in `agent.ts` now follows it. Before each step it asks the session for the history, and it keeps no messages of its own between steps. So no moment in the loop is special for recovery. The state at any point is the file, and a restart reads the same file the next step would have read.

The price is a read of the whole log before every step. [Part 2](/posts/the-roadmap/) asked what OpenCode gets in exchange for it; step 7 measures the price. OpenCode itself does not fold events on each read. It projects them into message tables as they are appended and loads the history from those tables ([core/src/session/sql.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/sql.ts#L86-L102), [core/src/session/history.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/history.ts#L277-L283)), so that a read does not replay the events. The agent here has one table and rebuilds the history on each read.

### 4. A failed turn is an event

[Part 5](/posts/why-effect/) dropped a failed turn by cutting the history array back to its length before the prompt. A log only grows, so the agent appends a `turn-failed` event, and `toHistory` leaves out every event from that turn's prompt through the failure. The file keeps the whole story, including the half-finished steps, and the model never sees a conversation that ends with a prompt nobody answered.

A crash is different from a failure. A provider error is caught, so the agent has time to append `turn-failed`. A killed process appends nothing. That absence is what the next run recognises as an unfinished turn.

### 5. A restart gives unfinished tool calls an error result instead of running them

A `step-finished` event without a matching `tool-result` means one of three things: the tool never started, it was running when the process died, or it finished and the process died before the result was appended. The log cannot tell them apart. Running the call again would be wrong in the second and third case, because a `bash` command or a `write_file` that already ran would run twice, and the user's earlier `y` does not cover a second run.

So the restart appends a `tool-result` of type error for each unanswered call: "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it." The model reads it as any other tool failure from [Part 5](/posts/why-effect/) and decides what to do, usually by looking at the files. OpenCode has the same problem and handles it in its own terms. Its step runner fails a tool that never settled with the error `Tool execution interrupted` ([core/src/session/runner/step.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/runner/step.ts#L60-L62)). Its restart sweep resumes an interrupted turn with the prompt "Continue from where you left off without repeating completed work", and a comment on the sweep states the guarantee: recovery is at-least-once, and it prevents concurrent drains but not repeated external side effects after a crash ([core/src/session/execution/restart.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/execution/restart.ts#L16-L17), [comment](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/session/execution/restart.ts#L53-L54)). The policy here is that a call with no result is not run again. It needs no sweep, no claims and no repeated prompt, and a call that never started is not run either, which the model can notice and repeat if it still matters.

### 6. Rows are checked when they are read

The database file is input from outside the program, like the arguments a model sends to a tool in [Part 5](/posts/why-effect/). It can be edited by hand, or written by an older version of the agent. Each row is decoded with an Effect Schema when it is read, and a row that no longer matches fails with a `SessionCorrupt` error that names the event's number. The program prints it and exits; it does not guess what the row meant. To make this possible without a second set of definitions, `messages.ts` now declares the message and part types as Schemas, and the TypeScript types come from them.

### What this leaves for later

A prompt is still written and run in the same act: if the process dies after the user pressed Enter and before the `prompt` event was appended, the prompt is lost. Separating the two is _Inbox vs. execution_ in [the roadmap](/posts/the-roadmap/). Only one process may write to a session: the event numbers are counted by the process that writes them, and a second writer on the same session fails with `UNIQUE constraint failed: event.session_id, event.seq` because the pair is the table's primary key. And a session never shrinks, so a long task will eventually outgrow the model's context window, which the roadmap's _Context limits and compaction_ covers.

### Step 1: The log table

Install the two runtime packages and Drizzle Kit, with exact versions, since the Effect driver is part of a release candidate:

```bash
bun add drizzle-orm@1.0.0-rc.5 @effect/sql-sqlite-bun@4.1.0
bun add -d drizzle-kit@1.0.0-rc.5
```

The table has one row per session event. `session_id` and `seq` together identify an event: `seq` counts from 1 within a session and gives the order. `type` repeats the event's type so that rows can be filtered by it without opening the JSON, and `data` holds the event as JSON (Drizzle's `mode: "json"` converts it on the way in and out). Columns are named in snake_case so the property name is the column name, which is also the convention in OpenCode's AGENTS.md. Create `src/session-table.ts`:

```ts
import { integer, primaryKey, sqliteTable, text } from "drizzle-orm/sqlite-core"

// The event log: one row per session event. `seq` orders the events of a session.
export const EventTable = sqliteTable(
  "event",
  {
    session_id: text().notNull(),
    seq: integer().notNull(),
    type: text().notNull(),
    data: text({ mode: "json" }).notNull(),
  },
  (table) => [primaryKey({ columns: [table.session_id, table.seq] })],
)
```

Drizzle Kit reads a small config file that says which SQL dialect to write, where the table declarations are and where to put the migrations. Create `drizzle.config.ts` in the project folder, next to `package.json`:

```ts
import { defineConfig } from "drizzle-kit"

export default defineConfig({
  dialect: "sqlite",
  schema: "./src/session-table.ts",
  out: "./drizzle",
})
```

Add a script to `package.json` so the command is the same everywhere:

```json
    "db:generate": "drizzle-kit generate",
```

Run it with `bun run db:generate --name event_log`; the script is needed because Drizzle Kit is installed in the project, not on the shell's path, so typing `drizzle-kit` alone fails with `command not found`. Drizzle Kit compares the declared tables with the snapshot of the previous migration, which does not exist yet, and writes the difference. ### Step 2: The Session service

This step builds everything that reads and writes the log, and leaves the agent alone. Start with the types. In `src/messages.ts`, replace the type declarations with Schemas, and derive the types from them. A Schema is one value that describes a shape. [Part 5](/posts/why-effect/) used one to check a tool's input, and here the same definition checks a message read back from the file. `Schema.mutable` keeps `content` an ordinary array, because the loop builds it with `push`. The two helpers at the end are as they were:

```ts
import { Schema } from "effect"

// The agent's own message types. No protocol appears in them. Each is a Schema, so the same definition
// that gives the type also checks the messages read back from the session log.
export const TextPart = Schema.Struct({ type: Schema.Literal("text"), text: Schema.String })
export const ToolCallPart = Schema.Struct({
  type: Schema.Literal("tool-call"),
  id: Schema.String,
  name: Schema.String,
  input: Schema.Unknown,
})
export const ToolResultValue = Schema.Struct({ type: Schema.Literals(["text", "error"]), value: Schema.String })
export const ToolResultPart = Schema.Struct({
  type: Schema.Literal("tool-result"),
  id: Schema.String,
  name: Schema.String,
  result: ToolResultValue,
})
export const Part = Schema.Union([TextPart, ToolCallPart, ToolResultPart])

export const Message = Schema.Struct({
  role: Schema.Literals(["user", "assistant", "tool"]),
  content: Schema.mutable(Schema.Array(Part)),
  // The provider's own content for this message, kept so the same protocol can send it back unchanged.
  native: Schema.optional(Schema.Unknown),
})

export type TextPart = typeof TextPart.Type
export type ToolCallPart = typeof ToolCallPart.Type
export type ToolResultValue = typeof ToolResultValue.Type
export type ToolResultPart = typeof ToolResultPart.Type
export type Part = typeof Part.Type
export type Message = typeof Message.Type

export const isToolCall = (part: Part): part is ToolCallPart => part.type === "tool-call"
export const textOf = (message: Message) => message.content.flatMap((part) => (part.type === "text" ? [part.text] : [])).join("\n")
```

In `src/errors.ts`, add the error for a row that does not decode, above `InputClosed`:

```ts
// A stored session event that no longer matches the schema, such as a file edited by hand or written by an older version.
export class SessionCorrupt extends Schema.TaggedError<SessionCorrupt>()("SessionCorrupt", {
  session: Schema.String,
  seq: Schema.Number,
  problem: Schema.String,
}) {
  override get message() {
    return `Session ${this.session} cannot be read: event ${this.seq} ${this.problem}`
  }
}
```

Create `src/session-event.ts` with the events from decision 1. Only three exist so far; `turn-failed` comes in step 4. Their payloads reuse the message Schemas:

```ts
import { Schema } from "effect"
import { Message, ToolResultPart } from "./messages"

// The facts a session records. Nothing here can be worked out from the other events.
export const Prompt = Schema.Struct({ type: Schema.Literal("prompt"), text: Schema.String })

// One finished model call: the whole assistant message and why the step ended.
export const StepFinished = Schema.Struct({
  type: Schema.Literal("step-finished"),
  message: Message,
  finish: Schema.Literals(["tool-calls", "stop", "refusal"]),
})

// One tool call's result. A step with three calls appends three of these, one as soon as each finishes.
export const ToolResult = Schema.Struct({ type: Schema.Literal("tool-result"), part: ToolResultPart })

export const SessionEvent = Schema.Union([Prompt, StepFinished, ToolResult])
export type SessionEvent = typeof SessionEvent.Type
```

Create `src/history.ts` with the fold from decision 2. It is a plain function from a list of events to a list of messages, with no database and no Effect:

```ts
import type { Message } from "./messages"
import type { SessionEvent } from "./session-event"

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []

  for (const event of events) {
    if (event.type === "prompt") {
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    }
  }
  return history
}
```

Now the service. It is declared like `Terminal` and `ModelClient` in [Part 6](/posts/services-and-layers/), by what the agent needs from it: an `id` to show the user, `append` to record a fact, and two Effects that read the log. `events` is the raw list and `history` is that list passed through `toHistory`. const encode = Schema.encodeSync(SessionEvent)

```ts
// the end of the program closes it. A disk failure is a defect, not something the agent can handle.
export const SessionLive = (options: { path: string; id: string }) =>

    Session,
    Effect.gen(function* () {
      const db = yield* SQLiteBunDrizzle.makeWithDefaults()
      yield* migrate(db, { migrationsFolder })

      const thisSession = eq(EventTable.session_id, options.id)

      // The numbering continues where the log stops. One process writes a session, so it can count for itself.
      const [last] = yield* db.select({ seq: max(EventTable.seq) }).from(EventTable).where(thisSession)
      let seq = last?.seq ?? 0

      // A row that no longer matches the schema stops the read and says which event it was.
      const readEvent = (row: typeof EventTable.$inferSelect) =>
        decode(row.data).pipe(
          Effect.mapError((error) => new SessionCorrupt({ session: options.id, seq: row.seq, problem: error.message })),
        )

      const events = db.select().from(EventTable).where(thisSession).orderBy(asc(EventTable.seq)).pipe(
        Effect.flatMap(Effect.forEach(readEvent)),
        Effect.catchTag("EffectDrizzleQueryError", Effect.die),
      )

      const append = (event: SessionEvent) =>
        Effect.suspend(() =>
          db.insert(EventTable).values({ session_id: options.id, seq: ++seq, type: event.type, data: encode(event) }),
        ).pipe(Effect.asVoid, Effect.orDie)

      return Session.of({ id: options.id, append, events, history: Effect.map(events, toHistory) })
    }).pipe(Effect.orDie),
  ).pipe(Layer.provide(SqliteClient.layer({ filename: options.path }).pipe(Layer.orDie)))
```

1. `migrationsFolder` is found relative to this file, because the agent runs from `playground/` and not from the project folder. `decode` and `encode` are the Schema's two directions.
2. Building the layer does the work that used to happen at import time, as in [Part 6](/posts/services-and-layers/). `makeWithDefaults()` creates the Drizzle database on top of the SQLite client, which the layer at the bottom of the file provides, and `migrate` applies the folder from step 1, creating the table on the first run.
3. A query is built with `db.select().from(table).where(...)` as in the Drizzle guide, and here it can be passed to `yield*`. `thisSession` is the condition shared by the queries, and the first query finds the highest event number in the log so that the numbering continues across restarts.
4. Reading is one query ordered by `seq`, then a decode of each row. A row that fails the Schema becomes a `SessionCorrupt` with the row's number. The query's own error, `EffectDrizzleQueryError`, means the disk or the file failed, which the agent cannot handle, so it becomes a defect ([Part 5](/posts/why-effect/)'s word for an error the program does not plan for) and ends up in the same place as other bugs.
5. Appending is one insert. The query builder is created inside `Effect.suspend`, so the number is taken when the append runs and not when the Effect is built. When the insert finishes, the row is in the file: the process can be killed on the next line and the event stays. (The SQLite client opens the file in WAL mode, write-ahead logging, in which changes are first written to a separate log file next to the database.)
6. The last lines are the layer's wiring. `Effect.orDie` turns the layer's own failures, such as a migration that cannot run, into defects, and `SqliteClient.layer` opens the file for the lifetime of the layer and closes it afterwards.

```ts
    const model = yield* ModelClient

    const history = yield* session.history
    const content: Part[] = []
```

Now `toHistory` has to act on `turn-failed`. As it reads the events from the oldest to the newest, it keeps a note called `turnStart`: the position in the message list where the latest prompt was added. When it reaches a `turn-failed` event, it removes every message from that position onward, so the prompt that failed and anything the turn added after it never reach the model. import type { Message } from "./messages"
```ts
import type { SessionEvent } from "./session-event"

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []
  let turnStart = 0 // where the current turn began, so a failed turn can be left out

  for (const event of events) {
    if (event.type === "prompt") {
      turnStart = history.length
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else if (event.type === "tool-result") {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    } else {
      history.length = turnStart
    }
  }
  return history
}
```

```ts
import { Effect, Stream } from "effect"
import { messageOf } from "./errors"
import type { FinishReason } from "./events"
import { isToolCall, type Message, type Part } from "./messages"
import { ModelClient } from "./model-client"
import { Session } from "./session"
import { Terminal } from "./terminal"
import { runTool, Tools, type Tool } from "./tool"

// One step: reload the history from the log, stream the model's events, show the text as it arrives,
// and append the finished message to the log.
const step = (tools: Tool[]) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const session = yield* Session
    const history = yield* session.history
    const content: Part[] = []
    let text = "" // the text block being written, if any
    const outcome: { finish: FinishReason; native?: unknown } = { finish: "stop" }

    // A text block ends when anything else arrives, or when the stream does, even by failing.
    const endText = Effect.suspend(() => {
      if (!text) return Effect.void
      content.push({ type: "text", text })
      text = ""
      return terminal.say("")
    })

    yield* Stream.runForEach(model.chat(history, tools), (event) =>
      Effect.gen(function* () {
        if (event.type === "text-delta") {
          if (!text) yield* terminal.write("Agent: ")
          text += event.text
          yield* terminal.write(event.text)
          return
        }
        yield* endText
        if (event.type === "tool-call") content.push(event)
        else {
          outcome.finish = event.reason
          outcome.native = event.native
        }
      }),
    ).pipe(Effect.ensuring(endText))

    const message: Message = { role: "assistant", content, ...(outcome.native === undefined ? {} : { native: outcome.native }) }
    yield* session.append({ type: "step-finished", message, finish: outcome.finish })
    return { message, finish: outcome.finish }
  })

// Steps until the model stops asking for tools. Each result is appended as soon as its tool finishes.
const run = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }
  }
})

// One prompt: record it, then run steps until the turn is over.
export const turn = (input: string) =>
  Effect.gen(function* () {
    const session = yield* Session
    yield* session.append({ type: "prompt", text: input })
    yield* run
  })
```

### Step 5: Resume what the last run left unfinished

`unansweredCalls` tells a restart where the last turn stopped. It looks at the end of the history and returns `undefined` if the turn finished, an empty list if the model has to answer next (the history ends with the user's message, or with tool results for every call), and the tool calls that have no result otherwise. In `src/history.ts`, change the import and add the function below `toHistory`:

```ts
import { isToolCall, type Message, type ToolCallPart } from "./messages"
```

```ts
// What a restart finds when the last turn did not finish: the tool calls of the last step that have no result yet.
// Returns undefined when the turn did finish, and an empty list when the model simply has to answer next.
export const unansweredCalls = (history: ReadonlyArray<Message>): ToolCallPart[] | undefined => {
  const last = history.at(-1)
  if (!last) return undefined
  if (last.role === "user") return []
  const assistant = last.role === "tool" ? history.at(-2) : last
  const calls = assistant?.content.filter(isToolCall) ?? []
  if (last.role === "assistant" && calls.length === 0) return undefined
  const answered = last.role === "tool" ? last.content.flatMap((part) => (part.type === "tool-result" ? [part.id] : [])) : []
  return calls.filter((call) => !answered.includes(call.id))
}
```

`resume` goes above `repl`. If the last turn is unfinished, it says so, appends the interrupted result for each unanswered call, and runs the loop. It does not run the interrupted tools. It prints each of them, so the user can see what the model is going to be told about:

```ts
const interrupted =
  "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it."

// A restart can find a turn that did not finish. Tool calls without a result get an error result instead of
// running again, since a command that already ran must not run twice. Then the turn continues.
const resume = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const calls = unansweredCalls(yield* session.history)
  if (calls === undefined) return

  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})
```

```ts
export const unansweredCalls = (history: ReadonlyArray<Message>): ToolCallPart[] | undefined => {
  const last = history.at(-1)
  if (!last) return undefined
  if (last.role === "user") return []
  const assistant = last.role === "tool" ? history.at(-2) : last
  const calls = assistant?.content.filter(isToolCall) ?? []
  if (last.role === "assistant" && calls.length === 0) return undefined
  const answered = last.role === "tool" ? last.content.flatMap((part) => (part.type === "tool-result" ? [part.id] : [])) : []
  return calls.filter((call) => !answered.includes(call.id))
}
```

```ts
import { Effect, Stream } from "effect"
import { messageOf, type InputClosed, type ProviderError, type SessionCorrupt } from "./errors"
import type { FinishReason } from "./events"
import { unansweredCalls } from "./history"
import { isToolCall, type Message, type Part } from "./messages"
import { ModelClient } from "./model-client"
import { Session } from "./session"
import { Terminal } from "./terminal"
import { runTool, Tools, type Tool } from "./tool"

// One step: reload the history from the log, stream the model's events, show the text as it arrives,
// and append the finished message to the log.
const step = (tools: Tool[]) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const session = yield* Session
    const history = yield* session.history
    const content: Part[] = []
    let text = "" // the text block being written, if any
    const outcome: { finish: FinishReason; native?: unknown } = { finish: "stop" }

    // A text block ends when anything else arrives, or when the stream does, even by failing.
    const endText = Effect.suspend(() => {
      if (!text) return Effect.void
      content.push({ type: "text", text })
      text = ""
      return terminal.say("")
    })

    yield* Stream.runForEach(model.chat(history, tools), (event) =>
      Effect.gen(function* () {
        if (event.type === "text-delta") {
          if (!text) yield* terminal.write("Agent: ")
          text += event.text
          yield* terminal.write(event.text)
          return
        }
        yield* endText
        if (event.type === "tool-call") content.push(event)
        else {
          outcome.finish = event.reason
          outcome.native = event.native
        }
      }),
    ).pipe(Effect.ensuring(endText))

    const message: Message = { role: "assistant", content, ...(outcome.native === undefined ? {} : { native: outcome.native }) }
    yield* session.append({ type: "step-finished", message, finish: outcome.finish })
    return { message, finish: outcome.finish }
  })

// Steps until the model stops asking for tools. Each result is appended as soon as its tool finishes.
const run = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }
  }
})

// One prompt: record it, then run steps until the turn is over.
export const turn = (input: string) =>
  Effect.gen(function* () {
    const session = yield* Session
    yield* session.append({ type: "prompt", text: input })
    yield* run
  })

const interrupted =
  "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it."

// A restart can find a turn that did not finish. Tool calls without a result get an error result instead of
// running again, since a command that already ran must not run twice. Then the turn continues.
const resume = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const calls = unansweredCalls(yield* session.history)
  if (calls === undefined) return

  yield* terminal.say(`[resuming session ${session.id}]`)
  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})

// The read-eval-print loop: finish an interrupted turn, then read a line from the user, run a turn on it,
// print the output, and repeat.
export const repl = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session

  // A turn that fails is recorded as failed, so the next prompt starts from a consistent history.
  const failed = (label: string, reason: string) =>
    session.append({ type: "turn-failed", reason }).pipe(Effect.andThen(terminal.say(`[${label}] ${reason}`)))
  const guarded = <R>(work: Effect.Effect<void, ProviderError | SessionCorrupt | InputClosed, R>) =>
    work.pipe(
      Effect.catchTag("ProviderError", (error) => failed("provider error", error.message)),
      Effect.catchDefect((defect) => failed("bug", messageOf(defect))),
    )

  yield* guarded(resume)
  while (true) {
    const input = yield* terminal.ask("You: ")
    yield* guarded(turn(input))
  }
}).pipe(Effect.catchTag("InputClosed", () => Effect.void))
```

**What the reload costs.** [Part 2](/posts/the-roadmap/) asked what rebuilding the history before every step buys, given that it is slower. It buys a loop with no second copy of the conversation to keep correct, and so a restart that is the same code as a normal step. This is the price. A log of 100, 1,000 and 10,000 events, in a mix of prompts, a step that calls a tool, a one-kilobyte tool result and a step that answers, was read and rebuilt into a history twenty times, including the query, the Schema decoding and the fold:

| Events in the log | File size | Rebuild the history (median) |
| ----------------- | --------- | ---------------------------- |
| 100               | 0.07 MB   | 0.2 ms                       |
| 1,000             | 0.61 MB   | 0.9 ms                       |
| 10,000            | 6.02 MB   | 8.7 ms                       |

A step takes seconds on the local models in [Part 7](/posts/streaming/) (the whole reply took 9.4 s on Ollama and 13.2 s on llama.cpp), so even the read of 10,000 events is under one per cent of a step. The cost grows with the log, which is what the projection tables in OpenCode are for.

> **Watch for this.** A result is appended after the tool returns, so a tool that finished just before the process died is reported as interrupted. The restart cannot distinguish this from a tool that was killed halfway, and the interrupted message says "may or may not have run" for that reason. The model resolves it by looking at the files, as it tried to in the transcript above.

> **Watch for this.** `migrationsFolder` is found from the location of `session.ts`. If the agent is copied or bundled without the `drizzle/` folder, the first run fails when it opens the database, with an error from the migrator and not from the agent. The folder is part of the program.

> **Result.** Every prompt, step and tool result is in a SQLite file the moment it happens, and the loop keeps nothing between steps. A process killed in the middle of a tool call leaves a log from which the next run finishes the turn, without running the tool a second time. A failed turn is part of the record and absent from the conversation. The cost of reading the log before each step is under ten milliseconds for ten thousand events.

```ts
// The agent's own message types. No protocol appears in them. Each is a Schema, so the same definition
// that gives the type also checks the messages read back from the session log.
export const TextPart = Schema.Struct({ type: Schema.Literal("text"), text: Schema.String })
export const ToolCallPart = Schema.Struct({
  type: Schema.Literal("tool-call"),
  id: Schema.String,
  name: Schema.String,
  input: Schema.Unknown,
})
export const ToolResultValue = Schema.Struct({ type: Schema.Literals(["text", "error"]), value: Schema.String })
export const ToolResultPart = Schema.Struct({
  type: Schema.Literal("tool-result"),
  id: Schema.String,
  name: Schema.String,
  result: ToolResultValue,
})
export const Part = Schema.Union([TextPart, ToolCallPart, ToolResultPart])

export const Message = Schema.Struct({
```

```ts
import { isToolCall, type Message, type ToolCallPart } from "./messages"
import type { SessionEvent } from "./session-event"

// The messages the next step sends to the model, rebuilt from the session events.
export const toHistory = (events: ReadonlyArray<SessionEvent>): Message[] => {
  const history: Message[] = []
  let turnStart = 0 // where the current turn began, so a failed turn can be left out

  for (const event of events) {
    if (event.type === "prompt") {
      turnStart = history.length
      history.push({ role: "user", content: [{ type: "text", text: event.text }] })
    } else if (event.type === "step-finished") {
      history.push(event.message)
    } else if (event.type === "tool-result") {
      // Results that follow one another belong to one tool message.
      const last = history.at(-1)
      if (last?.role === "tool") last.content.push(event.part)
      else history.push({ role: "tool", content: [event.part] })
    } else {
      history.length = turnStart
    }
  }
  return history
}

// What a restart finds when the last turn did not finish: the tool calls of the last step that have no result yet.
// Returns undefined when the turn did finish, and an empty list when the model simply has to answer next.
export const unansweredCalls = (history: ReadonlyArray<Message>): ToolCallPart[] | undefined => {
  const last = history.at(-1)
  if (!last) return undefined
  if (last.role === "user") return []
  const assistant = last.role === "tool" ? history.at(-2) : last
  const calls = assistant?.content.filter(isToolCall) ?? []
  if (last.role === "assistant" && calls.length === 0) return undefined
  const answered = last.role === "tool" ? last.content.flatMap((part) => (part.type === "tool-result" ? [part.id] : [])) : []
  return calls.filter((call) => !answered.includes(call.id))
}
```

```ts
export class Session extends Context.Service<
  Session,
  {
    readonly id: string
    readonly append: (event: SessionEvent) => Effect.Effect<void>
    // Every call reads the log again.
    readonly events: Effect.Effect<SessionEvent[], SessionCorrupt>
    readonly history: Effect.Effect<Message[], SessionCorrupt>
  }

const migrationsFolder = new URL("../drizzle", import.meta.url).pathname
const decode = Schema.decodeUnknownEffect(SessionEvent)
const encode = Schema.encodeSync(SessionEvent)

// The real session: a SQLite file. Building the layer opens the file and applies the migrations;
// the end of the program closes it. A disk failure is a defect, not something the agent can handle.
export const SessionLive = (options: { path: string; id: string }) =>
  Layer.effect(
    Session,
    Effect.gen(function* () {
      const db = yield* SQLiteBunDrizzle.makeWithDefaults()
      yield* migrate(db, { migrationsFolder })

      const thisSession = eq(EventTable.session_id, options.id)

      // The numbering continues where the log stops. One process writes a session, so it can count for itself.
      const [last] = yield* db.select({ seq: max(EventTable.seq) }).from(EventTable).where(thisSession)
      let seq = last?.seq ?? 0

      // A row that no longer matches the schema stops the read and says which event it was.
      const readEvent = (row: typeof EventTable.$inferSelect) =>
        decode(row.data).pipe(
          Effect.mapError((error) => new SessionCorrupt({ session: options.id, seq: row.seq, problem: error.message })),
        )

      const events = db.select().from(EventTable).where(thisSession).orderBy(asc(EventTable.seq)).pipe(
        Effect.flatMap(Effect.forEach(readEvent)),
        Effect.catchTag("EffectDrizzleQueryError", Effect.die),
      )

      const append = (event: SessionEvent) =>
        Effect.suspend(() =>
          db.insert(EventTable).values({ session_id: options.id, seq: ++seq, type: event.type, data: encode(event) }),
        ).pipe(Effect.asVoid, Effect.orDie)

      return Session.of({ id: options.id, append, events, history: Effect.map(events, toHistory) })
    }).pipe(Effect.orDie),
  ).pipe(Layer.provide(SqliteClient.layer({ filename: options.path }).pipe(Layer.orDie)))
```

```ts
import { Effect, Stream } from "effect"
import { messageOf, type InputClosed, type ProviderError, type SessionCorrupt } from "./errors"
import type { FinishReason } from "./events"
import { unansweredCalls } from "./history"
import { isToolCall, type Message, type Part } from "./messages"
import { ModelClient } from "./model-client"
import { Session } from "./session"
import { Terminal } from "./terminal"
import { runTool, Tools, type Tool } from "./tool"

// One step: reload the history from the log, stream the model's events, show the text as it arrives,
// and append the finished message to the log.
const step = (tools: Tool[]) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const session = yield* Session
    const history = yield* session.history
    const content: Part[] = []
    let text = "" // the text block being written, if any
    const outcome: { finish: FinishReason; native?: unknown } = { finish: "stop" }

    // A text block ends when anything else arrives, or when the stream does, even by failing.
    const endText = Effect.suspend(() => {
      if (!text) return Effect.void
      content.push({ type: "text", text })
      text = ""
      return terminal.say("")
    })

    yield* Stream.runForEach(model.chat(history, tools), (event) =>
      Effect.gen(function* () {
        if (event.type === "text-delta") {
          if (!text) yield* terminal.write("Agent: ")
          text += event.text
          yield* terminal.write(event.text)
          return
        }
        yield* endText
        if (event.type === "tool-call") content.push(event)
        else {
          outcome.finish = event.reason
          outcome.native = event.native
        }
      }),
    ).pipe(Effect.ensuring(endText))

    const message: Message = { role: "assistant", content, ...(outcome.native === undefined ? {} : { native: outcome.native }) }
    yield* session.append({ type: "step-finished", message, finish: outcome.finish })
    return { message, finish: outcome.finish }
  })

// Steps until the model stops asking for tools. Each result is appended as soon as its tool finishes.
const run = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const tools = yield* Tools

  while (true) {
    const { message, finish } = yield* step(tools)
    if (finish !== "tool-calls") return

    for (const call of message.content.filter(isToolCall)) {
      yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
      const part = yield* runTool(call)
      if (part.result.type === "error") yield* terminal.say(`[error] ${part.result.value}`)
      yield* session.append({ type: "tool-result", part })
    }
  }
})

// One prompt: record it, then run steps until the turn is over.
export const turn = (input: string) =>
  Effect.gen(function* () {
    const session = yield* Session
    yield* session.append({ type: "prompt", text: input })
    yield* run
  })

const interrupted =
  "The agent stopped before this tool finished, so it may or may not have run. Check the current state before repeating it."

// A restart can find a turn that did not finish. Tool calls without a result get an error result instead of
// running again, since a command that already ran must not run twice. Then the turn continues.
const resume = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session
  const calls = unansweredCalls(yield* session.history)
  if (calls === undefined) return

  yield* terminal.say(`[resuming session ${session.id}]`)
  for (const call of calls) {
    yield* terminal.say(`[interrupted] ${call.name}(${JSON.stringify(call.input)})`)
    yield* session.append({
      type: "tool-result",
      part: { type: "tool-result", id: call.id, name: call.name, result: { type: "error", value: interrupted } },
    })
  }
  yield* run
})

// The read-eval-print loop: finish an interrupted turn, then read a line from the user, run a turn on it,
// print the output, and repeat.
export const repl = Effect.gen(function* () {
  const terminal = yield* Terminal
  const session = yield* Session

  // A turn that fails is recorded as failed, so the next prompt starts from a consistent history.
  const failed = (label: string, reason: string) =>
    session.append({ type: "turn-failed", reason }).pipe(Effect.andThen(terminal.say(`[${label}] ${reason}`)))
  const guarded = <R>(work: Effect.Effect<void, ProviderError | SessionCorrupt | InputClosed, R>) =>
    work.pipe(
      Effect.catchTag("ProviderError", (error) => failed("provider error", error.message)),
      Effect.catchDefect((defect) => failed("bug", messageOf(defect))),
    )

  yield* guarded(resume)
  while (true) {
    const input = yield* terminal.ask("You: ")
    yield* guarded(turn(input))
  }
}).pipe(Effect.catchTag("InputClosed", () => Effect.void))
```

```ts
    const { requests } = await restart([reply("Done.")])

    expect(requests[0]?.map((message) => message.role)).toEqual(["user", "assistant", "tool"])
  })

  test("leaves a finished turn alone", async () => {
    await crashAfter([prompt("hi"), { type: "step-finished", message: { role: "assistant", content: [{ type: "text", text: "Hello." }] }, finish: "stop" }])

    const { requests, output } = await restart([])

    expect(requests).toEqual([])
    expect(output.join("\n")).not.toContain("resuming")
  })

  test("leaves a failed turn alone", async () => {
    await crashAfter([prompt("hi"), { type: "turn-failed", reason: "connection reset" }])

    const { requests, output } = await restart([])

    expect(requests).toEqual([])
    expect(output.join("\n")).not.toContain("resuming")
  })

  test("a resumed turn that calls a tool runs it like any other", async () => {
    ran.length = 0
    await crashAfter([prompt("go")])

    await restart([callTool("c9", "echo", { text: "again" }), reply("Done.")])

    expect(ran).toEqual(["again"])
  })
```

```ts
const using = <A, E>(id: string, use: (session: Session["Service"]) => Effect.Effect<A, E>) =>
  Effect.runPromise(Effect.gen(function* () { return yield* use(yield* Session) }).pipe(Effect.provide(SessionLive({ path, id }))))

  const events = await using("s", (session) => session.events)

  expect(events).toEqual([

    { type: "prompt", text: "two" },

  await using("b", (session) => session.append({ type: "prompt", text: "for b" }))

  expect(await using("b", (session) => session.events)).toEqual([{ type: "prompt", text: "for b" }])
```

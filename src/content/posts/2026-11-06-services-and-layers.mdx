## Foreword

This Part turns the model, the terminal and the tools of the agent from [Part 5](/posts/why-effect/) into services that the loop asks for, instead of things it imports. The loop can then be imported by a test and run against a scripted model: no server, no API key and no keyboard. It is the fourth Part of Stage A (Harness) in [the roadmap](/posts/the-roadmap/).

The code for this Part is available as the [`Part6_services_and_layers` snapshot of vfil/sigma-agent](https://github.com/vfil/sigma-agent/tree/Part6_services_and_layers), the repo where I build this agent in parallel.

## Start from what you cannot test

[Part 5](/posts/why-effect/) put every failure the agent can raise into a type. One thing is still out of reach of the compiler and of a test: the loop only runs against the real world. Each piece it needs is reached by an import, and each import does its work as soon as the file loads.

| Piece     | How the loop reaches it in Part 5                                                                          | What a test of the loop would need  |
| --------- | ---------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| The model | `provider.ts` reads `PROVIDER` and `ANTHROPIC_API_KEY` when the file is imported, and `chat` calls `fetch` | A running server, or a key          |
| The user  | `terminal.ts` opens readline on standard input when it is imported, and `tool.ts` imports `ask`            | Someone typing `y` and `n`          |
| The tools | `index.ts` imports the `tools` array                                                                       | Real files and real shell commands  |
| The loop  | `index.ts` builds `history`, defines `turn` and runs the program at the top level                          | Importing the loop starts the agent |

The first row shows in a small experiment. Importing `provider.ts` with an unknown provider name fails before any code of a test could run:


The environment is read when the file loads, so a test cannot pick a different one. The readline interface behaves the same way: importing `terminal.ts` attaches it to standard input, and the process stays tied to the keyboard until input ends.

This Part moves each of those pieces to the edge of the program. The loop asks for a model client, a terminal and a tools list, and `index.ts` is the only file that decides which real ones it gets. A test decides differently.

## What services and layers add

In [Part 5](/posts/why-effect/), `R` in `Effect<A, E, R>` stayed `never`. It is the list of things an Effect needs from its surroundings before it can run. Effect calls such a thing a **service** and the recipe that builds one a **layer**. Effect 4 defines services with `Context.Service`; the [v3 to v4 migration guide](https://github.com/Effect-TS/effect/blob/main/MIGRATION.md) lists how it replaces the v3 spellings. The snippets in this Part were run on Effect 4.1.0, the version OpenCode pins at the commit its links point to (`97be25f046`).

This section covers four ideas. Each snippet was run on its own before it went into this Part. To follow along, the snippets of an idea can be saved in a temporary file in `src`, such as `src/dice.ts`, and deleted afterwards.

### 1. A service is a key for something the program needs

A service is declared as a class. Its type parameters are the class itself and the shape of what it provides, and the string is its identifier. Inside `Effect.gen`, `yield*` on the class asks for the service:

```ts
import { Context, Effect, Layer } from "effect"

class Dice extends Context.Service<Dice, { readonly roll: Effect.Effect<number> }>()("Dice") {}

const play = Effect.gen(function* () {
  const dice = yield* Dice
  const first = yield* dice.roll
  const second = yield* dice.roll
  return first + second
})
// play: Effect<number, never, Dice>
```

`play` does not know how dice are rolled. Its type says only that it needs a `Dice`, in the third slot. The compiler refuses to run an Effect that still needs something:

```ts
await Effect.runPromise(play)
```

```text
$ bunx --package typescript tsc --noEmit
src/dice.ts(13,25): error TS2345: Argument of type 'Effect<number, never, Dice>' is not assignable to parameter of type 'Effect<number, never, never>'.
  Type 'Dice' is not assignable to type 'never'.
```

### 2. A layer builds a service, and providing it removes the requirement

`Layer.succeed` makes a layer from a value that already exists. `Effect.provide` gives a layer to an Effect, and the service disappears from `R`. Two layers for the same service give two behaviors for the same `play`:

```ts
const RealDice = Layer.succeed(Dice, Dice.of({ roll: Effect.sync(() => 1 + Math.floor(Math.random() * 6)) }))
const FixedDice = Layer.succeed(Dice, Dice.of({ roll: Effect.succeed(4) }))

console.log(await Effect.runPromise(play.pipe(Effect.provide(RealDice))))
console.log(await Effect.runPromise(play.pipe(Effect.provide(FixedDice))))
```

```text
$ bun src/dice.ts
11
8
```

The first number is random and differs between runs. The second is always 8, because `FixedDice` returns 4 every time. `play` is the same code in both runs, and the only difference is the layer.

### 3. A layer can run code, fail and need other services

`Layer.succeed` takes a finished value. `Layer.effect` takes an Effect that produces the service, so building the service can run code, read the environment, fail, and ask for other services. A layer has a type of its own, `Layer<Provided, Error, Required>`, so its failure and its requirements are visible in the same way as an Effect's.

When one layer needs the service another layer provides, `Layer.provide` connects them. OpenCode's tool layer asks for three services in its first lines, and its type carries them as requirements until they are provided ([core/src/tool.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/tool.ts)):

```ts
export class Service extends Context.Service<Service, Interface>()("@opencode/Tool") {}

const layer = Layer.effect(
  Service,
  Effect.gen(function* () {
    const hooks = yield* PluginHooks.Service
    const image = yield* Image.Service
    const permission = yield* Permission.Service
```

The agent in this Part needs none of that. None of its layers uses another service while it is built, so they are merged side by side.

### 4. A layer can open a resource and close it again

`Effect.acquireRelease` takes an Effect that opens something and a function that closes it. Inside `Layer.effect`, the resource lives as long as the program the layer was provided to:

```ts
class Database extends Context.Service<Database, { readonly query: (sql: string) => Effect.Effect<string> }>()("Database") {}

const DatabaseLive = Layer.effect(
  Database,
  Effect.gen(function* () {
    yield* Effect.acquireRelease(
      Effect.sync(() => console.log("open")),
      () => Effect.sync(() => console.log("close")),
    )
    return Database.of({ query: (sql) => Effect.sync(() => `rows for ${sql}`) })
  }),
)

const program = Effect.gen(function* () {
  const db = yield* Database
  console.log(yield* db.query("select 1"))
})

await Effect.runPromise(program.pipe(Effect.provide(DatabaseLive)))
console.log("done")
```

```text
$ bun src/database.ts
open
rows for select 1
close
done
```

`close` prints when the program ends, before the line that follows `runPromise`. The agent uses this for readline, which has to be opened once and closed at the end.

## Five decisions in the rewrite

### 1. Three services, named for what the loop needs

A service is a capability the agent asks for by name instead of importing it, and a layer is the recipe that builds one. The model client is the service that makes one step. The agent has three:

| Service       | What the loop uses                                                 | Live layer                                             | Test layer                              |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------------------ | --------------------------------------- |
| `ModelClient` | `chat(history, tools)`: one step, which fails with `ProviderError` | `ModelClientLive` selects a route from the environment | `scriptedModel`: replies from a list    |
| `Terminal`    | `ask(prompt)`, which fails with `InputClosed`, and `say(line)`     | `TerminalLive` opens readline and closes it at the end | `scriptedTerminal`: answers from a list |
| `Tools`       | The tool list the model is offered and `runTool` searches          | `ToolsLive` holds the five tools                       | A list of small fake tools              |

Permission is not a service in this Part. The y/n question stays on the tool as `confirm`, and it reaches the user through `Terminal`. OpenCode has a `Permission.Service` of its own; a later Part on permissions would build the equivalent.

### 2. A service's methods have no requirements of their own

Every method of `ModelClient` and `Terminal` returns an Effect whose `R` is `never`. `Terminal.ask` is `Effect<string, InputClosed>`, not an Effect that also asks for a readline interface. What a live layer needs to build the service stays inside the layer, and the code that uses the service sees only the service.

The requirements show up where a service is used. This Part moves the agent loop out of `index.ts` into two functions in a new file, `agent.ts`: `turn`, which handles one prompt, and `repl`, the read-eval-print loop, which reads a line from the user, runs a turn on it, prints the output and asks again until input ends (decision 4 covers the move). Asking the compiler for the types of the two functions with a deliberate type error (step 6 does this) gives:

```text
turn: Effect<void, ProviderError, ModelClient | Terminal | Tools>
repl: Effect<void, never, ModelClient | Terminal | Tools>
```

`R` is a union of everything the loop asks for, and `E` is what it can still fail with. `repl` has `never` there because it handles `ProviderError` and defects itself, as in Part 5.

### 3. The live layers hold what used to happen at import

`ModelClientLive` is a `Layer.effect`. Building it calls `selectRoute`, which now takes the environment as an argument and returns an Effect that can fail with a new `ConfigError`: an unknown `PROVIDER` or a missing `ANTHROPIC_API_KEY`. The layer's type, `Layer<ModelClient, ConfigError>`, makes that failure visible, and `index.ts` is where it is caught and printed.

`TerminalLive` opens readline with `Effect.acquireRelease`, so the interface is created when the layer is built and closed when the program ends. Importing `terminal.ts` no longer touches standard input.

### 4. The loop can be imported

`index.ts` used to create `history`, define the loop and run it. The loop now lives in `agent.ts` as the two functions from decision 2. `turn(history, input)` is one prompt: call the model until it stops asking for tools. `repl(history)` is the outer loop around it. `history` is an argument instead of a module-level array, so a test can start from an empty one and look at it afterwards.

`agent.ts` still imports files that contain real implementations, because `model-client.ts` holds both the service and its live layer, and `terminal.ts` does the same. That is harmless now, since nothing runs when a file loads: a live layer does its work only when something builds it. OpenCode puts a service and its layer in one file in the same way ([core/src/tool.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/src/tool.ts)).

### 5. A fake is a layer, and what it can and cannot tell you

`scriptedModel` returns replies from a list and records the history it receives at each step. It stores a copy, `[...history]`, because the loop keeps pushing messages onto the same history array after the call returns, so a stored reference would later show messages the model was never sent. `scriptedTerminal` returns answers from a list and records what the agent printed. The loop's code is the same in a test and in the real program. Only the layers differ.

OpenCode's tests use the same pattern for its model client, with `Layer.mock`, which accepts a partial implementation and fails when a method that was left out is called ([core/test/session-compact.test.ts](https://github.com/anomalyco/opencode/blob/97be25f046/packages/core/test/session-compact.test.ts)). The agent's services have one or two methods each, so its fakes implement all of them:

```ts
// The agent (test/fakes.ts, abridged)
export const scriptedModel = (steps: Step[]) => {
  const requests: Message[][] = []
  const layer = Layer.succeed(
    ModelClient,
    ModelClient.of({
      chat: (history) =>
        Effect.suspend(() => {
          requests.push([...history])
          // ... the next step of the script
        }),
    }),
  )
  return { layer, requests }
}
```

```ts
// OpenCode (session-compact.test.ts)
const client = Layer.mock(LLMClient.Service)({
  stream: (request: LLMRequest) => {
    requests.push(request)
    return Stream.make(LLMEvent.textDelta({ id: "summary", text: "manual session summary" }))
  },
  generate: () => Effect.die("unused"),
})
```

A scripted model checks the harness: that tool results go back in the right order, that a refusal reaches the model, that a failed turn leaves the history valid. It does not check the model. Whether a model picks the right tool or writes valid arguments is still decided by running it; [Part 1](/posts/the-loop/) used a run against Claude to tell a weak local model from a harness bug.

### Step 1: Move the loop into `agent.ts`

This step changes no behavior. `turn` and the outer loop leave `index.ts`, and `history` becomes an argument. Create `src/agent.ts`:

```ts
import { Effect } from "effect"
import { messageOf } from "./errors"
import { isToolCall, type Message, type ToolResultPart } from "./messages"
import { chat } from "./provider"
import { ask } from "./terminal"
import { runTool } from "./tool"
import { tools } from "./tools"

// One prompt: call the model until it stops asking for tools.
export const turn = (history: Message[], input: string) =>
  Effect.gen(function* () {
    history.push({ role: "user", content: [{ type: "text", text: input }] })

    while (true) {
      const { message, finish } = yield* chat(history, tools)
      history.push(message)
      for (const part of message.content) {
        if (part.type === "text" && part.text) console.log(`Agent: ${part.text}`)
      }
      if (finish !== "tool-calls") return

      const results: ToolResultPart[] = []
      for (const call of message.content.filter(isToolCall)) {
        console.log(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
        const result = yield* runTool(tools, call)
        if (result.result.type === "error") console.log(`[error] ${result.result.value}`)
        results.push(result)
      }
      history.push({ role: "tool", content: results })
    }
  })

// The read-eval-print loop: read a line from the user, run a turn on it, print the output, and repeat.
export const repl = (history: Message[]) =>
  Effect.gen(function* () {
    while (true) {
      const input = yield* ask("You: ")

      // A turn that fails is dropped from the history, so the next prompt starts from a consistent conversation.
      const before = history.length
      const drop = (label: string, reason: string) =>
        Effect.sync(() => {
          history.length = before
          console.log(`[${label}] ${reason}`)
        })

      yield* turn(history, input).pipe(
        Effect.catchTag("ProviderError", (error) => drop("provider error", error.message)),
        Effect.catchDefect((defect) => drop("bug", messageOf(defect))),
      )
    }
  }).pipe(Effect.catchTag("InputClosed", () => Effect.void))
```

`repl` is the read-eval-print loop: it reads a line, runs a turn on it, prints what the turn produced and repeats until input ends. Replace the contents of `src/index.ts` with:

```ts
import { Effect } from "effect"
import { repl } from "./agent"

await Effect.runPromise(repl([]))
```

Run `bunx --package typescript tsc --noEmit` and then the agent. It behaves as in Part 5.

### Step 2: The `Terminal` service

Replace `src/terminal.ts`. The class declares what the agent needs from the person at the keyboard. `TerminalLive` is the layer that builds it: it opens readline with `Effect.acquireRelease`, so closing it is part of the layer, and the code from Part 5 that turns a closed input into `InputClosed` moves inside. `say` replaces direct `console.log` calls:

```ts
import { Context, Effect, Layer } from "effect"
import { createInterface } from "node:readline/promises"
import { InputClosed } from "./errors"

// What the agent needs from the person at the keyboard. Nothing here says readline.
export class Terminal extends Context.Service<
  Terminal,
  {
    // Asks one question. The type says it can fail: input may have ended.
    readonly ask: (prompt: string) => Effect.Effect<string, InputClosed>
    readonly say: (line: string) => Effect.Effect<void>
  }
>()("@agent/Terminal") {}

// The real terminal. Building the layer opens readline; the end of the program closes it.
export const TerminalLive = Layer.effect(
  Terminal,
  Effect.gen(function* () {
    const rl = yield* Effect.acquireRelease(
      Effect.sync(() => createInterface({ input: process.stdin, output: process.stdout })),
      (rl) => Effect.sync(() => rl.close()),
    )

    // A pending question never settles when input ends, so ending input is turned into a rejection.
    const closed = new Promise<never>((_, reject) => rl.once("close", () => reject(new Error("input closed"))))
    closed.catch(() => {})

    return Terminal.of({
      ask: (prompt) =>
        Effect.tryPromise({
          try: () => Promise.race([rl.question(prompt), closed]),
          catch: () => new InputClosed(),
        }),
      say: (line) => Effect.sync(() => console.log(line)),
    })
  }),
)
```

```ts
import type { ToolCallPart, ToolResultPart, ToolResultValue } from "./messages"
import { Terminal } from "./terminal"

export type ToolFailure = UnknownTool | InvalidInput | Declined | ToolCrashed

export type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema, derived from the input Schema
  run: (input: unknown) => Effect.Effect<string, ToolFailure, Terminal>
}

const formatIssues = SchemaIssue.makeFormatterStandardSchemaV1()

// Builds a Tool from one Schema: it validates the input and produces the JSON Schema the model receives.
// `DecodingServices: never` limits S to Schemas that need nothing else to decode, so `run` keeps R = never.
export const defineTool = <S extends Schema.Struct<Schema.Struct.Fields> & { readonly DecodingServices: never }>(config: {
  name: string
  description: string
  input: S
  execute: (input: S["Type"]) => Promise<string>
  confirm?: (input: S["Type"]) => string // describes the action; when set, the user must approve it first
}): Tool => {
  const takes = Object.keys(config.input.fields).join(", ")
  const decode = Schema.decodeUnknownEffect(config.input)

  return {
    name: config.name,
    description: config.description,
    parameters: Schema.toJsonSchemaDocument(config.input).schema,
    run: (raw) =>
      Effect.gen(function* () {
        // A string is arguments that were not valid JSON; the protocol keeps the raw text.
        if (typeof raw === "string") {
          return yield* new InvalidInput({ tool: config.name, problems: [`the arguments are not valid JSON: ${raw}`], takes })
        }

        const input = yield* decode(raw, { errors: "all" }).pipe(
          Effect.mapError(
            (error) =>
              new InvalidInput({
                tool: config.name,
                problems: formatIssues(error.issue).issues.map((issue) => `${issue.path?.join(".") || "input"}: ${issue.message}`),
                takes,
              }),
          ),
        )

        if (config.confirm) {
          // No answer counts as "no".
          const terminal = yield* Terminal
          const answer = yield* terminal.ask(`Allow: ${config.confirm(input)}? [y/N] `).pipe(Effect.orElseSucceed(() => ""))
          if (answer.trim().toLowerCase() !== "y") return yield* new Declined()
        }

        return yield* Effect.tryPromise({
          try: () => config.execute(input),
          catch: (error) => new ToolCrashed({ tool: config.name, reason: messageOf(error) }),
        })
      }),
  }
}

// Cannot fail: every tool failure becomes a tool result the model can read.
export const runTool = (tools: Tool[], call: ToolCallPart): Effect.Effect<ToolResultPart, never, Terminal> => {
  const done = (result: ToolResultValue): ToolResultPart => ({ type: "tool-result", id: call.id, name: call.name, result })
  const tool = tools.find((tool) => tool.name === call.name)
  const run = tool ? tool.run(call.input) : Effect.fail(new UnknownTool({ name: call.name, available: tools.map((tool) => tool.name) }))

  return run.pipe(
    Effect.map((value) => done({ type: "text", value })),
    Effect.catch((failure) => Effect.succeed(done({ type: "error", value: failure.message }))),
  )
}
```

```ts
        fetch(`${route.baseUrl}${route.protocol.path}`, {

          headers: { "content-type": "application/json", ...route.headers },
```

Create `test/fakes.ts`. A `Step` is what the scripted model does next: a reply, or a `ProviderError`. `reply` and `callTool` build replies without the surrounding message. `scriptedModel` returns a layer and the list of histories it was sent (each one a copy, `[...history]`, because the loop keeps adding to the original), and `scriptedTerminal` returns a layer and everything the agent printed.
```ts
import { Effect, Layer } from "effect"
import { InputClosed, ProviderError } from "../src/errors"
import type { Message } from "../src/messages"
import { ModelClient } from "../src/model-client"
import type { Reply } from "../src/protocols"
import { Terminal } from "../src/terminal"

// Replies the scripted model gives, in order. A ProviderError makes that step fail instead.
export type Step = Reply | ProviderError

export const reply = (text: string): Step => ({ message: { role: "assistant", content: [{ type: "text", text }] }, finish: "stop" })

export const callTool = (id: string, name: string, input: unknown): Step => ({
  message: { role: "assistant", content: [{ type: "tool-call", id, name, input }] },
  finish: "tool-calls",
})

// A model that follows a script and records the history it was given at each step.
export const scriptedModel = (steps: Step[]) => {
  const requests: Message[][] = []
  const layer = Layer.succeed(
    ModelClient,
    ModelClient.of({
      chat: (history) =>
        Effect.suspend(() => {
          requests.push([...history])
          const next = steps[requests.length - 1]
          if (!next) return Effect.fail(new ProviderError({ reason: "The script has no reply left for this step" }))
          return next instanceof ProviderError ? Effect.fail(next) : Effect.succeed(next)
        }),
    }),
  )
  return { layer, requests }
}

// A terminal where the user types the given answers, in order. When they run out, input ends.
export const scriptedTerminal = (answers: string[]) => {
  const output: string[] = []
  const queue = [...answers]
  const layer = Layer.succeed(
    Terminal,
    Terminal.of({
      ask: (prompt) =>
        Effect.suspend(() => {
          output.push(prompt)
          const next = queue.shift()
          return next === undefined ? Effect.fail(new InputClosed()) : Effect.succeed(next)
        }),
      say: (line) => Effect.sync(() => void output.push(line)),
    }),
  )
  return { layer, output }
}
```

```ts
import { Effect } from "effect"
import { messageOf } from "./errors"
import { isToolCall, type Message, type ToolResultPart } from "./messages"
import { ModelClient } from "./model-client"
import { Terminal } from "./terminal"
import { runTool, Tools } from "./tool"

// One prompt: call the model until it stops asking for tools.
export const turn = (history: Message[], input: string) =>
  Effect.gen(function* () {
    const model = yield* ModelClient
    const terminal = yield* Terminal
    const tools = yield* Tools
    history.push({ role: "user", content: [{ type: "text", text: input }] })

    while (true) {
      const { message, finish } = yield* model.chat(history, tools)
      history.push(message)
      for (const part of message.content) {
        if (part.type === "text" && part.text) yield* terminal.say(`Agent: ${part.text}`)
      }
      if (finish !== "tool-calls") return

      const results: ToolResultPart[] = []
      for (const call of message.content.filter(isToolCall)) {
        yield* terminal.say(`[tool] ${call.name}(${JSON.stringify(call.input)})`)
        const result = yield* runTool(call)
        if (result.result.type === "error") yield* terminal.say(`[error] ${result.result.value}`)
        results.push(result)
      }
      history.push({ role: "tool", content: results })
    }
  })
```

```ts
  available: Schema.Array(Schema.String),

    return `Unknown tool: ${this.name}. Available tools: ${this.available.join(", ")}`
  }
}

  tool: Schema.String,
  problems: Schema.Array(Schema.String),
  takes: Schema.String,
}) {
  override get message() {
    return [`Invalid input for ${this.tool}:`, ...this.problems.map((problem) => `- ${problem}`), `${this.tool} takes an object with the fields: ${this.takes}`].join("\n")
  }
}

  override get message() {

  tool: Schema.String,
```

```ts
// The routes the agent knows. They read the environment they are given, so nothing happens at import time.
const routes = (env: Env): Record<string, Route> => ({
  ollama: { protocol: openaiChat, baseUrl: "http://127.0.0.1:11434/v1", headers: {}, model: "qwen3.5:9b" },
  llamacpp: { protocol: openaiChat, baseUrl: "http://127.0.0.1:9931/v1", headers: {}, model: "qwen3.5:9b" },

    model: "claude-sonnet-5-5",
  },

// PROVIDER picks the route. BASE_URL and MODEL override the route's defaults.
export const selectRoute = (env: Env): Effect.Effect<Route, ConfigError> => {
  const name = env.PROVIDER ?? "ollama"
  const selected = routes(env)[name]
  if (!selected) return Effect.fail(new ConfigError({ reason: `Unknown PROVIDER "${name}". Choose one of: ${Object.keys(routes(env)).join(", ")}` }))
  if (name === "claude" && !env.ANTHROPIC_API_KEY) return Effect.fail(new ConfigError({ reason: "Set ANTHROPIC_API_KEY first" }))
  return Effect.succeed({ ...selected, baseUrl: env.BASE_URL ?? selected.baseUrl, model: env.MODEL ?? selected.model })
}

// One step: one model call. It fails with a ProviderError that the user reads; the model never sees it.
export const chat = (route: Route, history: Message[], tools: Tool[]) =>
  Effect.gen(function* () {
    const unreachable = (error: unknown) => new ProviderError({ reason: `Could not reach ${route.baseUrl}: ${messageOf(error)}` })

    const response = yield* Effect.tryPromise({
      try: () =>
        fetch(`${route.baseUrl}${route.protocol.path}`, {
          method: "POST",
          headers: { "content-type": "application/json", ...route.headers },
          body: JSON.stringify(route.protocol.body(route.model, history, tools)),
        }),
      catch: unreachable,
    })
    const text = yield* Effect.tryPromise({ try: () => response.text(), catch: unreachable })
    if (!response.ok) return yield* new ProviderError({ reason: `${route.baseUrl} answered ${response.status}: ${text}` })

    return yield* Effect.try({
      try: (): Reply => route.protocol.decode(JSON.parse(text)),
      catch: (error) => new ProviderError({ reason: `Could not read the reply from ${route.baseUrl}: ${messageOf(error)}` }),
    })
  })
```

```ts
export class Terminal extends Context.Service<

      ask: (prompt) =>
        Effect.tryPromise({
          try: () => Promise.race([rl.question(prompt), closed]),
          catch: () => new InputClosed(),
        }),
      say: (line) => Effect.sync(() => console.log(line)),
```

```ts
import { Context, Effect, Schema, SchemaIssue } from "effect"
import { Declined, InvalidInput, messageOf, ToolCrashed, UnknownTool } from "./errors"
import type { ToolCallPart, ToolResultPart, ToolResultValue } from "./messages"
import { Terminal } from "./terminal"

export type ToolFailure = UnknownTool | InvalidInput | Declined | ToolCrashed

export type Tool = {
  name: string
  description: string
  parameters: Record<string, unknown> // JSON Schema, derived from the input Schema
  run: (input: unknown) => Effect.Effect<string, ToolFailure, Terminal>
}

// The tools the agent knows, as a service. Which tools exist is decided where the layer is built.
export class Tools extends Context.Service<Tools, Tool[]>()("@agent/Tools") {}

const formatIssues = SchemaIssue.makeFormatterStandardSchemaV1()

// Builds a Tool from one Schema: it validates the input and produces the JSON Schema the model receives.
// `DecodingServices: never` limits S to Schemas that need nothing else to decode, so `run` keeps R = never.
export const defineTool = <S extends Schema.Struct<Schema.Struct.Fields> & { readonly DecodingServices: never }>(config: {
  name: string
  description: string
  input: S
  execute: (input: S["Type"]) => Promise<string>
  confirm?: (input: S["Type"]) => string // describes the action; when set, the user must approve it first
}): Tool => {
  const takes = Object.keys(config.input.fields).join(", ")
  const decode = Schema.decodeUnknownEffect(config.input)

  return {
    name: config.name,
    description: config.description,
    parameters: Schema.toJsonSchemaDocument(config.input).schema,
    run: (raw) =>
      Effect.gen(function* () {
        // A string is arguments that were not valid JSON; the protocol keeps the raw text.
        if (typeof raw === "string") {
          return yield* new InvalidInput({ tool: config.name, problems: [`the arguments are not valid JSON: ${raw}`], takes })
        }

        const input = yield* decode(raw, { errors: "all" }).pipe(
          Effect.mapError(
            (error) =>
              new InvalidInput({
                tool: config.name,
                problems: formatIssues(error.issue).issues.map((issue) => `${issue.path?.join(".") || "input"}: ${issue.message}`),
                takes,
              }),
          ),
        )

        if (config.confirm) {
          // No answer counts as "no".
          const terminal = yield* Terminal
          const answer = yield* terminal.ask(`Allow: ${config.confirm(input)}? [y/N] `).pipe(Effect.orElseSucceed(() => ""))
          if (answer.trim().toLowerCase() !== "y") return yield* new Declined()
        }

        return yield* Effect.tryPromise({
          try: () => config.execute(input),
          catch: (error) => new ToolCrashed({ tool: config.name, reason: messageOf(error) }),
        })
      }),
  }
}

// Cannot fail: every tool failure becomes a tool result the model can read.
export const runTool = (call: ToolCallPart): Effect.Effect<ToolResultPart, never, Tools | Terminal> =>
  Effect.gen(function* () {
    const tools = yield* Tools
    const done = (result: ToolResultValue): ToolResultPart => ({ type: "tool-result", id: call.id, name: call.name, result })
    const tool = tools.find((tool) => tool.name === call.name)
    const run = tool ? tool.run(call.input) : Effect.fail(new UnknownTool({ name: call.name, available: tools.map((tool) => tool.name) }))

    return yield* run.pipe(
      Effect.map((value) => done({ type: "text", value })),
      Effect.catch((failure) => Effect.succeed(done({ type: "error", value: failure.message }))),
    )
  })
```

```ts
const editFile = async (path: string, oldStr: string, newStr: string) => {
  if (oldStr === newStr) throw new Error("old_str and new_str must be different")

  if (oldStr === "") {
    if (existsSync(path)) throw new Error(`${path} already exists; pass the text to replace as old_str`)
    await mkdir(dirname(path), { recursive: true })
    await writeFile(path, newStr)
    return `Created ${path}`
  }

  const content = await readFile(path, "utf8")
  const matches = content.split(oldStr).length - 1
  if (matches === 0) throw new Error(`old_str was not found in ${path}`)
  if (matches > 1) throw new Error(`old_str matches ${matches} places in ${path}; include more surrounding text`)
  await writeFile(path, content.replace(oldStr, () => newStr))
  return "OK"
}

  await mkdir(dirname(path), { recursive: true })

    })
```

```ts
import { Effect, Layer } from "effect"
import { InputClosed, ProviderError } from "../src/errors"
import type { Message } from "../src/messages"
import { ModelClient } from "../src/model-client"
import type { Reply } from "../src/protocols"
import { Terminal } from "../src/terminal"

// Replies the scripted model gives, in order. A ProviderError makes that step fail instead.
export type Step = Reply | ProviderError

export const reply = (text: string): Step => ({ message: { role: "assistant", content: [{ type: "text", text }] }, finish: "stop" })

export const callTool = (id: string, name: string, input: unknown): Step => ({
  message: { role: "assistant", content: [{ type: "tool-call", id, name, input }] },
  finish: "tool-calls",
})

// A model that follows a script and records the history it was given at each step.
export const scriptedModel = (steps: Step[]) => {
  const requests: Message[][] = []
  const layer = Layer.succeed(
    ModelClient,
    ModelClient.of({
      chat: (history) =>
        Effect.suspend(() => {
          requests.push([...history])
          const next = steps[requests.length - 1]
          if (!next) return Effect.fail(new ProviderError({ reason: "The script has no reply left for this step" }))
          return next instanceof ProviderError ? Effect.fail(next) : Effect.succeed(next)
        }),
    }),
  )
  return { layer, requests }
}

// A terminal where the user types the given answers, in order. When they run out, input ends.
export const scriptedTerminal = (answers: string[]) => {
  const output: string[] = []
  const queue = [...answers]
  const layer = Layer.succeed(
    Terminal,
    Terminal.of({
      ask: (prompt) =>
        Effect.suspend(() => {
          output.push(prompt)
          const next = queue.shift()
          return next === undefined ? Effect.fail(new InputClosed()) : Effect.succeed(next)
        }),
      say: (line) => Effect.sync(() => void output.push(line)),
    }),
  )
  return { layer, output }
}
```

```ts
// Two small tools, so the tests never touch the disk.
const echo = defineTool({
  name: "echo",
  description: "Returns its text.",
  input: Schema.Struct({ text: Schema.String }),
  execute: async ({ text }) => text,
})

const deleteEverything = defineTool({
  name: "delete_everything",
  description: "Pretends to delete everything.",
  input: Schema.Struct({}),
  execute: async () => "deleted",
  confirm: () => "delete everything",
})

// Runs the loop against a script and returns what the loop and the fakes saw.
const run = async (script: { model: Step[]; answers: string[] }) => {
  const model = scriptedModel(script.model)
  const terminal = scriptedTerminal(script.answers)
  const history: Message[] = []
  const layers = Layer.mergeAll(model.layer, terminal.layer, Layer.succeed(Tools, [echo, deleteEverything]))

  await Effect.runPromise(repl(history).pipe(Effect.provide(layers)))
  return { history, requests: model.requests, output: terminal.output }
}

describe("the agent loop", () => {
  test("runs a tool call and then answers", async () => {
    const { history, output } = await run({
      model: [callTool("call_1", "echo", { text: "hi" }), reply("The tool said hi.")],
      answers: ["say hi"],
    })

    expect(history.map((message) => message.role)).toEqual(["user", "assistant", "tool", "assistant"])
    expect(history[2]?.content).toEqual([{ type: "tool-result", id: "call_1", name: "echo", result: { type: "text", value: "hi" } }])
    expect(output).toContain("Agent: The tool said hi.")
  })

  test("tells the model when the user declines", async () => {
    const { requests } = await run({
      model: [callTool("call_1", "delete_everything", {}), reply("Understood, I will not delete anything.")],
      answers: ["clean up", "n"],
    })

    // The second request is the step after the tool call: its last message holds the result.
    const result = requests[1]?.at(-1)?.content[0]
    expect(result).toMatchObject({ type: "tool-result", result: { type: "error" } })
    expect(JSON.stringify(result)).toContain("User declined")
  })

  test("drops a turn whose model call fails", async () => {
    const { history, output } = await run({
      model: [new ProviderError({ reason: "connection refused" })],
      answers: ["hello"],
    })

    expect(history).toEqual([])
    expect(output).toContain("[provider error] connection refused")
  })
```
